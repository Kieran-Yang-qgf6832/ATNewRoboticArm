# 文档体系

四类公开文档，按「问题 → 决策 → 执行 → 变更」组织。**每类只有一个职责**：同一事实只在
一处写完整描述，其它地方只放链接。

| 目录 | 唯一职责 | 写什么 | 不写什么 |
| --- | --- | --- | --- |
| `execute/` | **照着做的操作步骤** | 命令、参数、判据、报错处理入口 | 排查过程、设计理由 |
| `adr/` | **决策与理由** | 背景、备选方案、后果、约束编号 | 逐步操作 |
| `bugs/` | **一个缺陷的生命周期** | 现象、根因、修复、验证、方法论 | 与操作无关的设计讨论 |
| `changelog/` | **对外可见的变化** | 改了什么、影响谁、怎么确认 | 根因排查过程（背景 ≤3 行） |

`docs/teach/` 是**本地教学材料**，被 `.git/info/exclude` 排除，不随仓库分发，也不在本索引内。

## 命名与维护

- `bugs/`、`adr/`、`changelog/` 使用 `YYYY-MM-DD/HHMM-中文短语.md`，日期取发现/决策/变更发生的时间；
- `execute/` 用 `NN-中文短语.md`，是稳定文档，不按日期分目录；
- 每个分类有 `README.md` 索引，新增条目后必须更新索引；
- **引用缺陷时直指条目文件**（如 `bugs/2026-10-13/1202-辨识加速度由速度二次求导.md`），
  不要再写 `docs/bugs.md O8` —— 该路径只是旧引用的兼容映射；
- **教学材料不要借用缺陷台账的编号**：台账会迁移，教学描述用自解释短语；
- 运行期日志不进入文档目录（`docs/log/` 已在 `.gitignore` 中忽略）；
- 机械检查脚本见 `docs/tools/check_docs.py`（索引存在性 + 相对链接）。
