# 让导纳和拖动示教在四轴机械臂上能用

（2026-10-18）

## 要解决的问题

项目现在的机械臂是四轴：前后摆、上下摆、左右那一小片、以及工具绕自己转一圈。但控制器里的两个“手把手”模式还是按六轴写的：

- **导纳**（让机械臂被推着走、按力让开）：四轴下一进去就被拒绝。
- **拖动示教**（用手拖着机械臂走）：四轴下一进去就报错，日志是“任务速度长度不对：要 4 个，给了 6 个”，然后退回空闲。

任务层虽然定义了 `admittance_move`（导纳轨迹）和 `teach`（拖动）两种步骤，但一条任务序列都没用过，实际不可用。

这次的目标：让这两个模式在四轴上能用——仿真里能被推着走、被拖着走，并且 tasks.yaml 里能直接调用。

## 做完是什么样

1. 仿真里在机械臂末端加一个推力，机械臂朝推的方向让开；力撤掉后停在原地，不自己回位。
2. 四个方向都能让：前后、上下、左右、工具自转。
3. 让开的速度有上限（初定 0.1 米/秒，可调），但没有位移上限——一直推会走到工作空间边上。
4. 仿真里加外力能拖动机械臂；松手立刻停，不会滑出去。
5. `tasks.yaml` 里新增两条演示序列（导纳、拖动），各自能用一条命令跑完、退出码 0。
6. 推的时候不抖；如果力估计本身有抖动，已经在用之前抹平过。

## 步骤

1. **先确认“力”能被读到。** 用仿真现成的外力服务在末端加一个已知的力，同时把控制器估出来的力打出来，确认方向和大小对得上。对不上的话后面所有手感都无从谈起，所以这一步先过。
2. **让拖动示教先能用。** 把拖动状态里还按六维写死的几处（姿态缓存、长度检查、日志）改成按四轴来，去掉“长度必须是 6”的检查。做完后：切到拖动不再报错，加外力能拖走，撤力就停。
3. **让导纳能用。** 去掉四轴下对导纳的拒绝；质量、阻尼、刚度都按四维来；刚度设为零（松手不回位）；给让开的速度加上限（初定 0.1 米/秒，做成参数）；力估计加一层简单平滑（如果第 1 步发现本来就干净，就留成可关的开关）。做完后：加推力会让开，撤力停在原地。
4. **接上任务层。** 在 `tasks.yaml` 加两条演示序列：一条导纳、一条拖动，都从空闲进出。做完后：两条序列一条命令跑通，退出码 0。导纳那条要配合外力脚本才有意义（否则只是普通轨迹跟踪），这一点写进序列注释。
5. **调手感、留档。** 用外力脚本反复试，把质量、阻尼调到“推得动、不抖、不窜”；把实际用的参数和整定方法写进 `ros2_controller.yaml` 注释，并在 `docs/bugs.md` 补一条记录（为什么四轴下这样定义、力和速度上限怎么定）。

## 不做什么

- 不做实机。力仍然用“实测力矩减模型力矩”来估，上实机前要再验证一次。
- 不做记录和回放（拖完就没了）。
- 不做位移上限（只限速度）。
- 不验证六轴模型（六轴路径保持现状）。
- 不新增步骤类型（`admittance_move` / `teach` 已经有了）。
- 不改 `cart_traj` / `joint_traj` 的现有行为。

## 完成情况（2026-10-18 实施）

**结论**：6 项「做完是什么样」全部达成，代价与边界记在 docs/bugs.md **O14**。

| 计划项 | 结果 |
| --- | --- |
| 1 推力方向让开、撤力停在原地 | ✅ 自由导纳分支；不施力 1.5 s 漂移 0.0000 m；撤力 1.2 s 后 1 s 内 < 0.5 mm |
| 2 四个方向都能让 | ✅ 前后 +5.4/−4.7 cm、上下 ±6.4 cm、工具自转 ±0.238 rad；**y 只有 1–2 cm 且方向不保证**（工作空间 4 cm，y 向雅可比最小） |
| 3 速度上限可调、无位移上限 | ✅ 平移模长 0.1 m/s / 自转 0.5 rad/s（热更新）；到边界回滚 + 速度清零、状态保持 |
| 4 外力能拖动、松手立刻停 | ✅ teach 零力模式；2 N / 0.6 s 拖走 13.3–27.8 cm，松手 1 s 内漂 3.6–5.4 mm |
| 5 两条演示序列、一条命令、退出码 0 | ✅ `admittance_demo` / `teach_demo`；验收入口 `src/launch_pack/tools/admittance_demo_check.py`（真实退出码） |
| 6 推的时候不抖 | ✅ 死区 0.5 N / 0.05 N·m + 10 Hz 低通 + 20 N / 3 N·m 限幅；力估计复核偏差 **0.7%**、方向余弦 1.000 |

**实施时额外做的（计划没写、但不做就不成立）**

1. **力估计符号是反的**：原代码把 `τ_act − RNEA` 当外力，实测 5 N 被估成 −4.76 N。
   不注入已知力根本发现不了（现象上「手臂动了」和「符号错」一样）。现在 `τ_ext = RNEA − τ_act`。
2. **K = 0 必须带死区**：无穷大直流增益会把任何模型偏差积成爬行。
3. **近奇异位形限幅**：零位形（完全伸直、z 向不可控）下 `Jᵀf = τ` 被 1/σ_min 放大，
   5 N 变 78 N / 12 N·m，直接把 joint4 推过限位；现在限幅到 20 N / 3 N·m，并且演示序列先
   `joint_move` 到 `ready` 再进导纳。
4. **参数热更新**：`admittance_*` 原来「能 set 但不生效」（C6 那类静默陷阱），改成
   `std::atomic` 快照真热更新。
5. **外力注入插件**：接进两个仿真 launch（`launch_pack/config/mujoco_plugins.yaml`）。
6. **示教序列要补 `idel` 步骤**：`teach` 只能从 idel 进，`joint_move` 结束后控制器停在
   `joint_traj` 的 STOP 阶段。

**与计划文字的偏差**

- 死区初值不是 1.5 N，而是 **0.5 N / 0.05 N·m**：实测静止时原始力估计只有 3e-8 N 量级
  （URDF 与 MuJoCo 模型同源），1.5 N 会把 2 N 的轻推全部吃掉。
- 「四条方向都能让」里的 **y 方向打了折扣**：它只能让开 1–2 cm，**而且让开方向不保证**
  （两次实测 +y 分别是 +1.1 cm 与 −6.9 mm）。原因是 y 工作空间只有 4 cm、y 向雅可比最小、
  力估计在该方向上最弱。验收对 y 只断言「对力有响应（|位移| ≥ 6 mm）」并记录符号。
- 验收判据用「推力段的平均速度」而不是瞬时峰值：撤力瞬间位置环会弹回，瞬时速度必然超限速。
- 新增话题 `/arm_controller/admittance_estimate`（第 1 步的力估计读出口）。
