# 06 参数辨识

参数辨识由三部分组成：控制器 `measure` 状态生成激励轨迹并记录 CSV；离线
`parameter_identify` 用 FIGAROH 辨识；结果回写 URDF/YAML 报告。

## 快速流程

```bash
# 1) 一条命令起仿真并跑测量（CSV 默认落在项目根目录）
ros2 launch launch_pack arm_measure_sim.launch.py

# 2) 离线辨识
ros2 run parameter_identify identify_arm \
  --csv measured_for_identification.csv \
  --urdf src/arm_model/model/robotic_arm.urdf \
  --output /tmp/robotic_arm_identified.urdf \
  --config src/parameter_identify/config/identify.yaml \
  --report /tmp/robotic_arm_identify_report.yaml
```

常用 launch 覆盖参数：`csv_file_path` / `trajectory_period` / `trajectory_repeat_cnt` /
`move_to_start_duration` / `controller_urdf_path` / `step_timeout` / `trajectory_seed`
（0 = 随机，非 0 = 可复现）。测量默认 headless。

## 关键事实

- 测量直接记录 MuJoCo 的真实 `qacc` 与**仿真时间**，不再对速度二次求导（O8）；
- 激励轨迹带关节限位、地面净空、自碰撞/连杆-地面碰撞、指令力矩可行性约束（O11、O12）；
- 生成约 50 s，`step_timeout` 默认 240 s；
- 默认 `physical_projection: true`，因为真值模型本身贴在物理可行集边界上；
- **不要把辨识输出当成下一轮辨识的先验**：可辨识的只有 36 个基参数，其余落在零空间，
  反复喂回去会让误差单调放大（C7，30 轮 0.29% → 272.7%）。

## 验证

不要看报告里的 `rmse`——它量的是最小二乘基参数，而写进 URDF 的是投影之后的参数。
用：

```bash
python3 src/parameter_identify/tools/verify_torque.py \
  --urdf /tmp/robotic_arm_identified.urdf \
  --csv measured_for_identification.csv
```

拿最终 URDF 正演一遍：训练集 + 另一条轨迹 + 与真值模型对比 + 残差与 |dq| 的相关性。

## 实机限制

实机 MCU 不上报加速度，`acc_*` 列恒 0；`measure` 在 `real_mode: true` 下被拒绝。
需要参数辨识请回仿真链路。
