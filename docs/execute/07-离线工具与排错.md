# 07 离线工具与排错

## 离线工具

`src/arm_controller/tools/` 下的工具**不安装**，构建后在 `build/arm_controller/`：

| 工具 | 用途 |
| --- | --- |
| `fk_dump <urdf> <q1..q6>` | 打印 FK 平移、四元数、旋转矩阵、任务空间 6 维向量 |
| `ik_solve [--axis|--position] [--accept-axis <deg>] [--accept-position <m>] <urdf> <t0..t5> <s0..s5>` | 单次逆解，报告三态结果、残余、耗时；两个 `--accept-*` 可回到严格判据做 A/B |
| `ik_benchmark` | 批量采样统计收敛率与迭代次数 |
| `arm_real_joint_count_test` | 不连硬件校验实机接口的 5/6/7 关节处理 |
| `joint_calibrate` | 单关节点动标定；`-p print_zero:=true` 打印可粘贴的 zero 片段 |
| `waypoint_planner_test` | 多路点 C3 规划器离线自检 |

其他验收工具：

| 工具 | 用途 |
| --- | --- |

## 5 维角容差的 A/B 复核

`ik_solve --axis` 默认按控制器 yaml 的两档判据跑（收敛 1°、通过 5°）；加
`--accept-axis 1` 就退回「只有收敛判据」。同一目标、同一初值各跑一次，能确认放宽分支
真的生效而不是被别处的容差吞掉：

```bash
source install/setup.bash
URDF=src/arm_model/model/robotic_arm.urdf
# 目标 = axis_limit_pos + 一条比 joint5 限位方向多 4° 的工具轴；初值 = joint5 压上限的位形
T="-0.519350 -0.004953 1.131781 -0.629046 2.532347 0.175048"
S="0.0 0.3 -0.3 0.0 0.4 0.0"
./build/arm_controller/ik_solve --axis $URDF $T $S
./build/arm_controller/ik_solve --axis --accept-axis 1.0 $URDF $T $S
```

实测（2026-11-14）：目标位置残余 2.2e-5 m、工具轴残余 1.875°。默认档
`Converged` + `relaxed_accept = yes`；`--accept-axis 1` 同一残余下报 `Unreachable`。
两次 `ik_err` 完全相同，说明差别只在判定，不影响迭代结果。

> 这条 A/B 只能证明求解器的判定逻辑。想用仿真序列复现放宽分支做不到：6 自由度下
> 「位置 ≤1 mm、工具轴差 1°~5°」的目标基本只出现在局部极小，换个初值就消失
> （`pos_axis_limit_probe` 实测最终 0.11°）。见
> [验证记录](../bugs/2026-11-14/1710-5维放宽容差的可达性验证.md)。

位置也有一个同构的**通过**容差（`IKSolver::set_solve_options()` 的第 5 个参数，
由 `CartTrajCmd.position_pass_tolerance` 按轨迹下发），离线用 `--accept-position <m>`
做同样的 A/B。实测（ready 位形沿工具轴外推 0.35 m 的目标，初值 ready）：

```bash
T="-0.349649 0.114644 0.850477 -2.729827943 -0.121476469 -0.759644657"   # ready 沿工具轴外推 0.35 m
S="0 0.3 -0.3 0 0.3 0"
./build/arm_controller/ik_solve --axis $URDF $T $S
./build/arm_controller/ik_solve --axis --accept-position 0.05 $URDF $T $S
```

严格档报 `Unreachable`（最近可达差 5.77 mm / 2.98°）；`--accept-position 0.05`
报 `Converged` + `relaxed_position = yes`（同一残余的 2.98° 也落在工具轴的放宽区间，
所以 `relaxed_axis` 同时为 yes）。把外推量加到 0.45 m（5.22 cm）后两档都拒绝；
外推 0.65 m 时位置 4.96 cm 但工具轴差 11.6°，也判拒绝——位置与工具轴是**各自**判据。
仿真里对应的 WARN 是 `target accepted with the relaxed position pass tolerance:
nearest reachable pose is ...`，任务层按同一个 `tolerance` 验收。

## rosbag 出图

`ros2 run launch_pack plot_rosbag [bag]`：读 `.ros/ros2bags` 下的 bag（省略路径时取最新一个并回显），
每个关节出一张 PNG（位置 / 速度 / 力矩的命令 vs 反馈 + 位置误差）和一份同名 HTML（plotly 交互版），
写到 `docs/rosbags/<bag 名>/joint1..joint6.{png,html}`（重跑覆盖；该目录已在 `.gitignore` 里）。

```bash
ros2 run launch_pack plot_rosbag                                      # 最新 bag
ros2 run launch_pack plot_rosbag .ros/ros2bags/arm_sim_20261114-145209
ros2 run launch_pack plot_rosbag <bag> --out-dir /tmp/plots --dpi 180
ros2 run launch_pack plot_rosbag <bag> --no-feedback                   # 只画命令，不画反馈
ros2 run launch_pack plot_rosbag <bag> --no-html                       # 只要 PNG
```

- `--no-feedback` 只隐藏反馈曲线，时间轴与关节集合仍取 `/joint_states`；位置误差子图留空，
  并用「已关闭反馈绘制」标注。输出文件名不变，会覆盖同一 bag 之前出的图。
- x 轴用消息的 `header.stamp`（命令与状态同一时钟，仿真里是仿真时间）；`/arm_controller/state`
  没有 header，靠 `/joint_states` 的「接收时间 → header 时间」映射换到同一时钟，首条状态之前留空。
- **不画加速度**：`JointState` 没有该字段、实机也不上报，差分值只能看趋势（录制口径见
  [02 仿真运行 § 关节命令/状态录制](02-仿真运行.md#关节命令状态录制rosbag)）。
- 命令 `effort` 是前馈力矩，反馈 `effort` 是执行器实际出力（仿真 `qfrc_actuator` / 实机 MCU 上报），
  两者不是「目标 vs 实测」，不要当误差看。
- 旧 bag 没有 `/arm_controller/joint_command` 时自动降级为只画反馈，并在标题与终端标注。

HTML 交互图（默认与 PNG 一起出，`--no-html` 关掉）：

- 每个关节一份 `<joint>.html`，内容与 PNG 同构（四格 + 状态带），但**全量样本**入图、
  WebGL 渲染、不抽稀：PNG 里 1 px 挤好几个样本的 93 Hz 命令，这里放大后是逐点真值。
- 四格共享 x 轴，x 轴统一悬停（同一时刻命令与反馈并排读数）+ 竖向准星（画在当前子图里），
  滚轮/框选缩放四格同步。
- 打开时自动聚焦「命令位置变化最快」的 ±5 s，双击回到全时段；初始视角不影响任何数据。
- 同目录只落一份 `plotly.min.js`，断网也能打开；单独把 HTML 拷走会丢它，要连目录一起拷。
- 依赖浏览器 WebGL：不支持时只会显示一行提示，那就看 PNG。

## 力矩脉冲自检（idel，`test_torque_*`）

给**单个关节**叠加一个已知符号的短力矩（`|τ| ≤ 5 N·m`、`≤ 0.5 s`、只在 `idel` 生效、到点自动归零），
用来判断**下行**力矩通道的符号。这是标定步骤，流程与判据见
[04 实机首次运行与标定 § 5.5 标定重力力矩方向](04-实机首次运行与标定.md#55-标定重力力矩方向torque_dir)；
本节只说工具语义：

```bash
ros2 param set /arm_controller test_torque_duration 0.2
ros2 param set /arm_controller test_torque_value 2.0
ros2 param set /arm_controller test_torque_joint 2     # 最后写关节号：三个参数齐了才会触发
```

- 只能单关节、一次一脉冲；越界写入（`|value| > 5`、`duration > 0.5`、`joint > 关节数`）会被参数回调
  直接拒绝，不会静默生效。
- 脉冲开始/结束各打一条 WARN（结束那条带 `elapsed`）；参数写好后 **30 s 内**没被 `idel` 消费则作废，
  防止「几十秒后突然一脚」。
- 幅度为什么是 2 N·m：固件位置环等效刚度实测约 2600 N·m/rad，2 N·m ≈ 0.8 mrad，是位置抖动
  （±0.3 mrad）的 2–3 倍；0.5 N·m 只有 0.19 mrad，读不出方向。
- 这条通道只测**下行**符号；上行 `effort` 反号是另一件事（见 [O21](../bugs/2026-11-22/1007-保持与轨迹力矩交接仍是阶跃.md)），
  不影响臂往哪边走。

## 常见报错

| 日志 / 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Failed to open USB CDC device vid=0x0483 pid=0x5741` | udev 规则没生效 / 没重插线 / 固件 PID 不符 | 回 [实机首次运行](04-实机首次运行与标定.md) Phase 2 |
| `超过 100 ms 未收到 MCU 状态包` | 固件没跑 / 帧协议不匹配 / USB 接触不良 | 查下位机供电与固件版本（应为 `2026_R2_NEW_ARM_LOWER`：帧头 `int32 0x01`，下行 78 B / 上行 77 B）；换线 |
| `URDF 声明了 N 个关节，但 MCU 通信帧固定为 6 个电机` | 关节数被改过 | 恢复 `joint1..joint6` |
| `关节标定文件 ... 无效，拒绝启动` | YAML 缺 `joints` / `dir` 不是 ±1 / `zero` 非有限 | 按标定页逐项核对 |
| `无法把控制器切到 joint_traj` | 控制器没激活 / 节点名不是 `arm_controller` | `ros2 control list_controllers` |
| `position-constrained trajectory REJECTED ... allow_constrained_traj=false` | 实机默认关闭位置约束轨迹 | 先做 [real-compat 验收](05-任务层与序列.md#real-compat-验收序列)，再改配置并重启 |
| `设置 exp_state: teach_pendant 或 measure 失败` | `real_mode: true` 的正常拒绝 | 实机不支持，回仿真 |
| 机械臂反方向动 / 冲限位 | `dir` 填反了 | 立刻急停，重新标定 |
| `joint6 is outside its model limit` | 6 维目标在 5 自由度下越限 | 用 `joint_console` 或重算目标点 |
| `未提供 joint_calibration_file，按 dir=1/zero=0 直接透传。` | URDF 里 `<param name="joint_calibration_file">` 丢了 | 检查 `src/arm_model/model/robotic_arm.urdf` 的 `hardware:=real` 段 |
| `10 s 内没有收到 /joint_states，退出` | `joint_state_broadcaster` 没起 / 话题被重映射 | `ros2 topic list \| grep joint_states`；`ros2 control list_controllers` |
| 机械臂静止时角度**不是 0**，但姿态看起来对 | `zero` 没标定 | 回 [实机首次运行](04-实机首次运行与标定.md) Phase 5.4 |

## 排错原则

1. 先看**控制器日志**的 `cart constraint:` / `激励约束：` 行，确认实际生效参数；
2. 参数写了不等于生效：控制器只读 `auto_declare` 过的参数（C6）；
3. 不可达目标在下发前被拒绝是**正确行为**，不要先改容差；
4. 涉及辨识结果，先跑 `verify_torque.py`，不要信报告里的 `rmse`；
5. 实机断链不会停机（R5），任何自动任务前先确认物理急停可用。
