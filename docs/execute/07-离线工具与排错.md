# 07 离线工具与排错

## 离线工具

`src/arm_controller/tools/` 下的工具**不安装**，构建后在 `build/arm_controller/`：

| 工具 | 用途 |
| --- | --- |
| `fk_dump <urdf> <q1..q6>` | 打印 FK 平移、四元数、旋转矩阵、任务空间 6 维向量 |
| `ik_solve [--axis|--position] <urdf> <t0..t5> <s0..s5>` | 单次逆解，报告三态结果、残余、耗时 |
| `ik_benchmark` | 批量采样统计收敛率与迭代次数 |
| `arm_real_joint_count_test` | 不连硬件校验实机接口的 5/6/7 关节处理 |
| `joint_calibrate` | 单关节点动标定；`-p print_zero:=true` 打印可粘贴的 zero 片段 |
| `waypoint_planner_test` | 多路点 C3 规划器离线自检 |

其他验收工具：

| 工具 | 用途 |
| --- | --- |
| `ros2 run view check_sim_vision` | 仿真视觉数值验收 |
| `ros2 run tasks waypoint_check` | 多路点轨迹验收（轨迹执行前启动） |
| `ros2 run launch_pack plot_rosbag [bag]` | 把 bag 里的关节命令/状态画成逐关节 PNG（见下） |
| `src/parameter_identify/tools/verify_torque.py` | 拿最终 URDF 正演验证力矩 |
| `src/parameter_identify/tools/check_collision.py` | 用 CSV 实际关节角复算碰撞距离 |

## rosbag 出图

`ros2 run launch_pack plot_rosbag [bag]`：读 `.ros/ros2bags` 下的 bag（省略路径时取最新一个并回显），
每个关节出一张 PNG（位置 / 速度 / 力矩的命令 vs 反馈 + 位置误差），写到
`docs/rosbags/<bag 名>/joint1..joint6.png`（重跑覆盖；该目录已在 `.gitignore` 里）。

```bash
ros2 run launch_pack plot_rosbag                                      # 最新 bag
ros2 run launch_pack plot_rosbag .ros/ros2bags/arm_sim_20261114-145209
ros2 run launch_pack plot_rosbag <bag> --out-dir /tmp/plots --dpi 180
ros2 run launch_pack plot_rosbag <bag> --no-feedback                   # 只画命令，不画反馈
```

- `--no-feedback` 只隐藏反馈曲线，时间轴与关节集合仍取 `/joint_states`；位置误差子图留空，
  并用「已关闭反馈绘制」标注。输出文件名不变，会覆盖同一 bag 之前出的图。
- x 轴用消息的 `header.stamp`（命令与状态同一时钟，仿真里是仿真时间）；`/arm_controller/state`
  没有 header，靠 `/joint_states` 的「接收时间 → header 时间」映射换到同一时钟，首条状态之前留空。
- **不画加速度**：`JointState` 没有该字段、实机也不上报，差分值只能看趋势（录制口径见
  [02 仿真运行 § 关节命令/状态录制](02-仿真运行.md#关节命令状态录制rosbag)）。
- 命令 `effort` 是前馈力矩，反馈 `effort` 是执行器实际出力（仿真 `qfrc_actuator` / 实机 MCU 上报），
  两者不是「目标 vs 实测」，不要当误差看。
- 旧 bag 没有 `/arm_controller/joint_command` 时自动降级为只画反馈，并在标题与终端标注。

## 常见报错

| 日志 / 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Failed to open USB CDC device vid=0x0483 pid=0x5741` | udev 规则没生效 / 没重插线 / 固件 PID 不符 | 回 [实机首次运行](04-实机首次运行与标定.md) Phase 2 |
| `超过 100 ms 未收到 MCU 状态包` | 固件没跑 / 帧协议不匹配 / USB 接触不良 | 查下位机供电与固件版本（应为 `2026_R2_NEW_ARM_LOWER`：帧头 `int32 0x01`，下行 78 B / 上行 77 B）；换线 |
| `URDF 声明了 N 个关节，但 MCU 通信帧固定为 6 个电机` | 关节数被改过 | 恢复 `joint1..joint6` |
| `关节标定文件 ... 无效，拒绝启动` | YAML 缺 `joints` / `dir` 不是 ±1 / `zero` 非有限 | 按标定页逐项核对 |
| `无法把控制器切到 joint_traj` | 控制器没激活 / 节点名不是 `arm_controller` | `ros2 control list_controllers` |
| `position-constrained trajectory REJECTED ... allow_constrained_traj=false` | 实机默认关闭位置约束轨迹 | 先做 [real-compat 验收](05-任务层与序列.md#real-compat-验收序列)，再改配置并重启 |
| `设置 exp_state: teach_pendant 或 measure 失败` | `real_mode: true` 的正常拒绝 | 实机不支持，回仿真 |
| 机械臂反方向动 / 冲限位 | `dir` 填反了 | 立刻急停，重新标定 |
| `joint6 is outside its model limit` | 6 维目标在 5 自由度下越限 | 用 `joint_console` 或重算目标点 |
| `未提供 joint_calibration_file，按 dir=1/zero=0 直接透传。` | URDF 里 `<param name="joint_calibration_file">` 丢了 | 检查 `src/arm_model/model/robotic_arm.urdf` 的 `hardware:=real` 段 |
| `10 s 内没有收到 /joint_states，退出` | `joint_state_broadcaster` 没起 / 话题被重映射 | `ros2 topic list \| grep joint_states`；`ros2 control list_controllers` |
| 机械臂静止时角度**不是 0**，但姿态看起来对 | `zero` 没标定 | 回 [实机首次运行](04-实机首次运行与标定.md) Phase 5.4 |

## 排错原则

1. 先看**控制器日志**的 `cart constraint:` / `激励约束：` 行，确认实际生效参数；
2. 参数写了不等于生效：控制器只读 `auto_declare` 过的参数（C6）；
3. 不可达目标在下发前被拒绝是**正确行为**，不要先改容差；
4. 涉及辨识结果，先跑 `verify_torque.py`，不要信报告里的 `rmse`；
5. 实机断链不会停机（R5），任何自动任务前先确认物理急停可用。
