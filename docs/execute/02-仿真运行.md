# 02 仿真运行

## 直接起仿真

```bash
source /opt/ros/jazzy/setup.bash && source install/setup.bash

# 仿真 + RViz
ros2 launch launch_pack arm_controller_test_sim.launch.py

# 无界面（纯命令行）
ros2 launch launch_pack arm_controller_test_sim.launch.py headless:=true show_rviz:=false
```

控制器激活后会自动执行一次 `reset`（`exp_state: reset`），把机械臂拉到零位并回到 `idel`。

## 模型文件

`src/arm_model/model/` 下的模型自 2026-11-14 起来自**新一代实机 CAD**，替换了旧一代
（旧模型与真机的连杆长度差 20~80 mm）。决策与取舍见
[机械臂模型换代 ADR](../adr/2026-11-14/1546-机械臂模型换代.md)。

| 文件 | 用途 |
| --- | --- |
| `robotic_arm.urdf` | 运动学/动力学与 `<ros2_control>`；mujoco 与 real 两个硬件分支由 `hardware:=` 切换 |
| `robotic_arm.xml` | MJCF 主模型（body、惯量、限位、执行器、自碰撞排除） |
| `robotic_arm_real_compat.xml` | 与主模型只差 `motor6 gear=0`，供 5 自由度仿真用 |
| `scene.xml` | 默认场景（辨识/测量），地面参与碰撞 |
| `scene_vision.xml` / `scene_vision_raised.xml` | 视觉验证（相机 + 红色目标箱，两档高度） |
| `scene_real_compat.xml` / `scene_vision_raised_real_compat.xml` | 上述场景的 5 自由度变体（锁 joint6） |

改模型时必须守住的三条：

- **URDF `<limit>` 与 MJCF `<joint range>` 逐项一致**——不一致时 IK 会停在控制器认为
  非法的位形上，表现为莫名其妙的求解失败，见
  [MJCF 与 URDF 关节限位不一致](../bugs/2026-10-08/1716-MJCF与URDF关节限位不一致.md)；
- **`effort` 保持 50 N·m**：控制器 `measure_traj_torque_limit_rate: 0.6` 是按 50 N·m 折算
  力矩门禁的，直接沿用 CAD 导出的 100 会让门禁静默放宽一倍；
- **`scene.xml` 的地面保持 `contype=1 conaffinity=1`**：`measure_traj_ground_clearance`
  靠它挡住机械臂，见[激励轨迹撞地面污染辨识](../bugs/2026-10-13/2226-激励轨迹撞地面污染辨识.md)。

关节轴约定（CAD 原值，未规范化）：joint2 / joint3 / joint4 为 `0 0 -1`，joint5 的轴相对
工具 z 倾斜 3.28°。`robotic_arm_real_compat.xml` 必须随主模型同步重生，否则会停在旧几何上。

## 一条龙：仿真 + 任务（推荐）

```bash
# 默认打开 Qt joint_console；任务/UI 退出后自动关仿真
ros2 launch launch_pack arm_task_sim.launch.py

# 任意序列
ros2 launch launch_pack arm_task_sim.launch.py task_sequence:=pos_move_demo

# 常驻，之后可改参数换序列
ros2 launch launch_pack arm_task_sim.launch.py exit_when_idle:=false
ros2 param set /task_runner task_sequence "pick_demo"
```

常用 launch 参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `task_sequence` | `joint_console_ui` | `tasks.yaml` 里的序列名 |
| `tasks_config` | `tasks/config/tasks.yaml` | 任务 YAML 路径 |
| `mujoco_model` | `arm_model/model/scene.xml` | MJCF 场景 |
| `headless` | `false` | 关掉 MuJoCo UI |
| `show_rviz` | `false` | 是否启动 RViz |
| `controller_overlay` | 空映射 | 控制器参数叠加文件（real-compat 用） |
| `exit_when_idle` | `true` | 任务结束后是否关掉整个 launch |
| `record_bag` | `true` | 是否录 rosbag（关节命令 + 关节状态） |
| `bag_dir` | `<项目根>/.ros/ros2bags` | rosbag 输出根目录（空 = 该默认值） |

## 关节命令/状态录制（rosbag）

启动控制器时默认就在录，仿真与实机用同一份实现（`launch_pack/launch/arm_bag_record.launch.py`）：

| 话题 | 类型 | 内容 |
| --- | --- | --- |
| `/joint_states` | `sensor_msgs/msg/JointState` | 下位机回报的关节状态（MuJoCo 状态 / 实机 MCU 反馈） |
| `/arm_controller/joint_command` | `sensor_msgs/msg/JointState` | 上位机每周期**真正写进命令接口**的关节命令（position/velocity/effort） |
| `/arm_controller/state` | `std_msgs/msg/String` | 控制器实际状态（`idel` / `reset` / `joint_traj` …） |
| `/arm_joint_traj`、`/arm_joint_waypoints`、`/arm_servo` | `robot_msgs/*` | 任务层下发的关节空间指令（意图，非每周期命令） |

输出目录 `~/MyProjects/2027ATRobotArm_LowerAndUpper/ATNewRoboticArm_Upper/.ros/ros2bags/<arm_sim|arm_real>_<YYYYmmdd-HHMMSS>/`
（mcap）——即**项目根的 `.ros/ros2bags`**，该目录在 `.gitignore` 里，不会进版本库。
可用 `bag_dir` 改根目录、`bag_storage:=sqlite3` 换存储插件。

```bash
# 关掉录制
ros2 launch launch_pack arm_controller_test_sim.launch.py record_bag:=false
# 换输出位置（默认是 <项目根>/.ros/ros2bags）
ros2 launch launch_pack arm_task_sim.launch.py bag_dir:=/data/bags

# 查看与回放
ros2 bag info .ros/ros2bags/arm_sim_20261114-140239
ros2 bag play .ros/ros2bags/arm_sim_20261114-140239
```

录完直接出图：`ros2 run launch_pack plot_rosbag`（每个关节一张 PNG，落在 `docs/rosbags/<bag 名>/`，
详见 [07 离线工具 § rosbag 出图](07-离线工具与排错.md#rosbag-出图)）。

要点：

- `joint_command` 以 **100 Hz** 发布（`update()` 是 500 Hz，5 倍降采样；实机 MCU 下行帧也是 100 Hz），
  取的是**最终写入命令接口**的值，故障保持路径下发的保持命令同样录得到。
- 仿真里 bag 的**接收时间戳是墙钟**：不给 Python 节点开仿真时间（设计约束 C9，500 Hz 的 `/clock`
  会吃掉一个核）。对齐命令与状态请用消息的 `header.stamp`——两者都取自控制周期，是同一个时钟。
- 只录上表这些话题，`/tf` 不在其中；需要时另开 `ros2 bag record -a`。
- `Ctrl-C` 结束 launch 时 rosbag2 正常收尾（写 `metadata.yaml`）。日志里出现
  `process has died ... exit code 2` 是 rosbag2 的 Python 收尾竞态，`ros2 bag info` 能读到完整数据即正常；
  **不要 `kill -9`**，否则 bag 不可读。

## 控制器状态

| 状态 | 用途 |
| --- | --- |
| `idel` | 锁定当前位置（带重力前馈） |
| `reset` | 复位到 `reset_joint_pos` |
| `cart_traj` | 笛卡尔轨迹（含 `pos_move` / `box_move`） |
| `joint_traj` | 关节轨迹（含多路点） |
| `servo` | 速度积分伺服 |
| `admittance` | 导纳控制 |
| `teach_pendant` | 示教拖动 |
| `measure` | 参数辨识测量 |

```bash
ros2 param set /arm_controller exp_state reset
ros2 param get /arm_controller exp_state
```

## 多路点轨迹

`joint_waypoints` / `cart_waypoints` 是控制器内建的 C3 轨迹：

```bash
ros2 run tasks waypoint_check --mode joint --expected '[[0,0,0,0,0,0]]'
```

必须在轨迹执行前启动，等待 `/arm_waypoints_duration`。详见 [任务层与序列](05-任务层与序列.md)。
