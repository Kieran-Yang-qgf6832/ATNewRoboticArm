# 10 · 基座运动补偿 / 末端惯性空间保持

基座在 world 系里按 x/y 平移 + yaw 转向运动，末端保持进入状态那一刻的 world 位姿不变。
决策背景与取舍见 [ADR-20261124-1200](../adr/2026-11-24/1200-基座运动补偿与惯性空间保持.md)。

## 1. 一键跑起来

```bash
source install/setup.bash
ros2 launch arm_base_motion inertial_hold_sim.launch.py
# 无窗口/无 RViz（批处理、录数据）
ros2 launch arm_base_motion inertial_hold_sim.launch.py headless:=true show_rviz:=false
```

这一条 launch 会：

1. 从 `arm_model/model/robotic_arm.xml` 生成 mocap 基座变体到 `$TMPDIR/arm_base_motion`，
   并生成 `scene_base_motion.xml`（源模型与现有 5 个场景零改动）；
2. 用 `launch_pack/arm_controller_test_sim.launch.py` 起 MuJoCo + 控制器链，
   `floating_base:=true`（URDF 去掉 `world_to_base`）、叠加
   `arm_base_motion/config/inertial_hold_overlay.yaml`；
3. 起 `base_motion_tf_node`，按基座话题发布 `world→base_link`；
4. `switch_hold_after`（默认 8 s）把控制器从 `reset` 切到 `inertial_hold`；
5. 基座插件在 `start_delay`（overlay 里 12 s）之后开始跑轨迹。

RViz 的固定帧是 `world`：应该看到基座在平移/转向，而末端基本钉在原地。

## 2. 看什么

| 话题 | 内容 |
|---|---|
| `/base_motion_state` | 基座 world 系位姿 + 线/角速度 + 线/角加速度（500 Hz，解析值） |
| `/arm_controller/inertial_hold_status` | 目标/实测末端位姿、位置与姿态误差、`base_state_valid`、`ik_converged`（200 Hz） |
| `/arm_controller/state` | 控制器实际状态（应为 `inertial_hold`） |
| `/joint_states`、`/arm_controller/joint_command` | 实测与下发命令，用于看关节层跟踪 |

```bash
ros2 topic echo /arm_controller/inertial_hold_status --once
ros2 param get /arm_controller current_state
```

## 3. 量化验收

```bash
ros2 run arm_base_motion evaluate_inertial_hold.py --duration 30 --output-dir /tmp/hold_eval
```

评估窗口从 `base_motion_state.motion_active` 第一次为真的那一帧开始（基座静止段不计入），
输出：

- `inertial_hold_error.csv`：`stamp_ns, position_error_m, orientation_error_rad, base_state_valid, ik_converged`
- `inertial_hold_error.png`：误差时间曲线 + 门槛参考线
- 终端统计：位置/姿态 RMS 与峰值、基座状态可用率、逆解收敛率、PASS/FAIL

默认门槛（暂定，首轮实测后可修订）：位置峰值 ≤ 5 mm、RMS ≤ 2 mm、姿态峰值 ≤ 0.5°。

2026-11-24 的基线：位置 RMS 0.42 mm / 峰值 0.70 mm，姿态 RMS 0.18° / 峰值 0.36°，
基座状态与逆解收敛率均 100%，PASS。

## 4. 配置

### 控制器（`arm_base_motion/config/inertial_hold_overlay.yaml`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `exp_state` | `reset` | 上电先复位；launch 定时切 `inertial_hold` |
| `reset_joint_pos` | `[0,0,2.0,-1.0,0,0]` | 折叠位形，**不能是全零**（零位是近奇异全伸展） |
| `inertial_hold_kp` / `_kd` | `[600,600,600,80,40,220]` / `[20,20,20,2,1,0.7]` | 该状态专用刚度；为空时逐项回落 `default_kp/kd`。joint6 不能再高（400 实测发散） |
| `base_motion_topic` | `/base_motion_state` | 必须绝对名（插件在子命名空间发布） |
| `base_state_timeout` | `0.1` | 超时即冻结指令（不切状态） |
| `inertial_hold_max_extrapolation` | `0.05` | 用 v/a 外推到当前时刻的上限 |
| `inertial_hold_ik_iterations` | `10` | 热启动下的迭代上限，防止极端位形吃满 2 ms 周期 |
| `inertial_hold_velocity_ff` | `1.0` | 速度前馈缩放；0 = 关闭（A/B），负值 = 反向（验符号） |

改这些参数需要重启控制器（构造期读取）。

### 基座轨迹（同一文件 `mujoco_ros2_control_node` 段）

| 参数 | 默认 | 说明 |
|---|---|---|
| `body` | `base_link` | 必须是 mocap body |
| `topic` | `/base_motion_state` | 发布话题 |
| `start_delay` | `12.0` | 延时结束后起跑；延时内基座钉在初始位姿 |
| `x_amplitude` / `x_frequency` / `x_phase` | `0.15` / `0.20` / `0` | x 正弦（m、Hz、rad） |
| `y_amplitude` / `y_frequency` / `y_phase` | `0.10` / `0.32` / `0` | y 正弦 |
| `yaw_amplitude_deg` / `yaw_frequency` / `yaw_phase` | `15` / `0.10` / `0` | yaw 正弦（度、Hz、rad） |

轨迹会减掉 `sin(φ)` 保证从初始位形连续起步；频率取不同值，合成李萨如式运动。

## 5. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 启动就报 `Nan, Inf or huge value in QACC` | 基座模型没生效（仍是固定基座或 freejoint 方案），检查 launch 日志里的 `BaseMotionPlugin initialised on mocap body` |
| 日志刷「基座状态已 …ms 未更新」 | 话题名不一致：插件在 `mujoco_ros2_control_node/<plugin>` 下发布，必须用绝对名；`ros2 topic list | grep base_motion` 确认 |
| 整段「逆解未收敛」 | 起始位形太伸展（可达域边界）。换 `reset_joint_pos` 或减小幅值 |
| 关节被顶出限位、姿态误差几十度 | 刚度太高：joint6 上限约 300、joint5 保持 40 以内（见 ADR「踩到的坑」） |
| 位置误差几十 mm | 检查 `base_link`/`link1` 是否在蹭地面（`--base-z` 默认 0.06，网格低于基座原点约 34 mm） |
| 构建本包报 `No module named 'catkin_pkg'` | 当前 shell 的 `python3` 不是系统解释器（例如 pixi/conda 抢先）。加 `--cmake-args -DPython3_EXECUTABLE=/usr/bin/python3` |

## 6. 实机

`real_mode: true` 时 `inertial_hold` 会被参数服务拒绝进入：该状态的全部输入来自仿真侧
基座话题，实机上不存在。将来接底盘时把状态从 `state_unavailable_on_real` 的白名单里摘掉，
并让底盘按同一消息格式发布 `BaseMotionState` 即可（平面基座假设仍然成立）。
