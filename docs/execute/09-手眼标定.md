# 09 手眼标定（eye_on_base）

相机固定在支架上俯视工作区，标靶装在末端 `link6` 上随机械臂走；标定结果是一条静态变换
`base_link -> camera_link`，供视觉链路把目标从相机系换到机器人系。

> 这轮只做标定链路本身：`box_move` 与 `red_quad_detector` 不做任何改动。
> 标定完成后要接进业务链，需要另行重算箱体粗定位点。

## 0. 一次性准备

### 标靶参数（`calib.io_CHARUCO_200x150_8x11_15_11_DICT_4X4.pdf`）

| 项 | 值 |
| --- | --- |
| 纸面 | 200 × 150 mm |
| 板面 | 165 × 120 mm（横向 17.5 mm、纵向 15 mm 边距） |
| 格数 | 11 列 × 8 行 |
| 格 / marker | 15 mm / 11 mm |
| 字典 / 数量 | `DICT_4X4_50`，44 个（ID 0~43） |
| 相位 | 左上角是白格，ID 0 在 (列 0, 行 0) |

打印必须 100% 缩放（不要"适应纸张"）。打完后量**左上白格左边缘 → 最右黑格右边缘 = 165 mm**，
误差超过 0.5 mm 重打，否则手眼结果会带系统偏差。

### 构建

```bash
source install/setup.bash
colcon build --packages-select view launch_pack --symlink-install
```

## 1. 启动（两个终端，先机械臂后视觉）

`calib.launch.py` **不含机器人控制节点**：它只起相机、检测节点和 easy_handeye2 的采样界面。
`base_link -> link6` 的 TF 与 `/joint_states` 来自 `arm_real.launch.py`，没起它的话
`handeye_server` 会卡在等 TF，`joint_console_ui` 也发不出指令。

```bash
# 终端 1：机械臂（无硬件冒烟用 loopback:=true）
ros2 launch launch_pack arm_real.launch.py
# 等 controller_manager 把 arm_controller 激活

# 终端 2：视觉 + 采样界面
ros2 launch view calib.launch.py
```

终端 2 拉起：RealSense（`848x480x30` + 对齐深度）、`calib_board_detector`、easy_handeye2
的 dummy 静态发布器（`base_link -> camera_link`）、`handeye_server` 与 `rqt_calibrator`。
默认参数已经是整条链路的正确取值：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `calibration_type` | `eye_on_base` | 相机固定、标靶随动 |
| `tracking_base_frame` | `camera_link` | **不要填光学帧**，见下 |
| `tracking_marker_frame` | `calib_board` | 与检测节点 `child_frame_id` 一致 |
| `robot_base_frame` | `base_link` | |
| `robot_effector_frame` | `link6` | |
| `name` | `arm5dof_realsense` | 决定 `.calib` 文件名 |

相机已在别处跑：`start_camera:=false`；只想调试检测：`start_handeye:=false`。

> **采样阶段不要同时起 `handeye.launch.py`**：easy_handeye2 的 dummy 发布器发的也是
> `base_link -> camera_link`（值 1,0,0），和真实外参抢同一个子帧，TF 可能取到假的那条。
> 复测阶段反过来——用 `start_handeye:=false` 关掉 dummy，再起 `handeye.launch.py`。

> **为什么 `tracking_base_frame` 不是 `camera_color_optical_frame`**：`calibrate.launch.py`
> 自带一个 dummy 静态发布器，会发 `base_link -> tracking_base_frame`；而光学帧在 RealSense
> 驱动里已经有父帧 `camera_color_frame`，同一个子帧两个父帧会覆盖驱动那段 TF。
> 填 `camera_link` 正好占住驱动 TF 链的根，链路是
> `base_link → camera_link → camera_color_frame → camera_color_optical_frame → calib_board`。

## 2. 摆位与采样

仓库里没有 MoveIt，easy_handeye2 的 `handeye_server_robot`（自动枚举位姿）起不来，必须手动摆
（下面这条命令依赖终端 1 的 `arm_controller` 已激活）：

```bash
ros2 run tasks task_runner --ros-args -p task_sequence:=joint_console_ui
```

每摆好一个姿态停 1 s，在 rqt 里点 **Take Sample**，凑 15~20 个姿态。要求：

- 平移覆盖工作区不同位置（不要只转手腕）；
- 板面相对相机的倾角跨越 30°~60°；
- 板子完整落在视野内、不被机械臂自身遮挡；
- 每换一个姿态先看预览窗口左侧的 `markers` 与 `rms`，`rms` 突然变大先别采样。

预览窗口按 `q` 退出（关掉预览不影响 TF 发布）。

## 3. 导出与使用

`easy_handeye2` 只会写 `~/.ros2/easy_handeye2/calibrations/<name>.calib`，导出到项目：

```bash
mkdir -p .ros/easy_handeye2
cp ~/.ros2/easy_handeye2/calibrations/arm5dof_realsense.calib .ros/easy_handeye2/
```

`.ros/` 在 `.gitignore` 里，属于本机资产：换机器或动过支架必须重标。

发布外参（任何需要相机系→机器人系的场合）：

```bash
ros2 launch launch_pack handeye.launch.py
# 或显式指定：calib_file:=/abs/path/xxx.calib
```

它读 `.calib` 里的 `transform` 发静态 TF，帧名取 `parameters.robot_base_frame` /
`tracking_base_frame`，所以和标定时用的 frame 名不会不一致。

## 4. 验收

只看 rqt 里的采样残差不够——残差小只说明采样没抖，抓不到轴向或内参这类系统性错误。
把标靶**从末端拆下来固定在桌面**，关掉 dummy 并发布真实外参，然后起复测脚本：

```bash
# 终端 2 改成：不要 dummy，只保留相机与检测
ros2 launch view calib.launch.py start_handeye:=false

# 终端 3：真实外参 + 复测
ros2 launch launch_pack handeye.launch.py
ros2 run view check_handeye
```

机械臂仍由终端 1 的 `arm_real.launch.py` 提供 TF（复测本身只用 TF，不用动臂）。

摆 5 个以上不同姿态，每个停 1 s 以上；脚本按 1 s 间隔自动分组，实时打印每组位姿，
凑够组数后给出组间离散度：

- 通过标准：位置标准差 ≤ 5 mm、角度标准差 ≤ 1°；
- 退出码 0 = 通过。

超限时的排查顺序：

1. 位置超限：先怀疑检测——板子是否平整、是否 100% 缩放打印（应 165 mm）、`rms` 是否正常；
2. 角度超限：怀疑 frame 方向与标定类型，再看相机内参；
3. 两者都超：把 `.calib` 删掉重标，并确认采样时机械臂真的停稳了。

## 5. 已知坑

- **rqt 窗口不出现**：不是 rqt 坏了。`handeye_server` 只在 `wait_for_tf_init()` 成功后才
  创建采样服务，`rqt_calibrator` 又在 `HandeyeClient.__init__` 里阻塞等待这些服务，
  所以缺 `base_link -> link6`（没起 `arm_real.launch.py`）时窗口**永远不显示**，
  日志里能看到 `Waiting for sampling services` 与反复的
  `"link6" passed to lookupTransform argument source_frame does not exist`。
  补起机械臂即可，服务出现后窗口会自动弹出（服务端每 2 s 重试一次）。
- **不要用 `cv2.aruco.CharucoBoard(11, 8, 15, 11, ...)`**：这张板的白格相位与 OpenCV
  内置模板相反（内置模板左上角是黑格、ID 0 在第二格），直接建板实测重投影误差 160 px。
  节点里按实物布局自己生成 44 个 marker 的三维角点，用 176 个角点 `solvePnP`。
- **不要用 `cv2.aruco.Board(...)` + `estimatePoseBoard`**：Ubuntu 24.04 的 `python3-opencv`
  4.6.0 里这个构造函数直接段错误，用 `solvePnP` 绕开。
- 系统 OpenCV 是 4.6，没有 `CharucoDetector`（4.7+ 才有），也没有 `getBoardObjectAndImagePoints`。
- 内参用 RealSense 出厂值；重投影 `rms` 长期大于 1.5 px 再考虑用这块板自标内参。
- 检测节点订阅 QoS 默认 `sensor`（与真实驱动一致）；换到仿真环境要 `image_qos:=reliable`。
