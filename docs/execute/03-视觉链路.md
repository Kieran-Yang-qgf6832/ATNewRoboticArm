# 03 视觉链路

## 仿真链路

```
model_4dof/scene_vision.xml（固定深度相机 + 红色目标箱）
  └── CameraPlugin → /vision_camera/{color, depth, camera_info}
        └── view/red_quad_detector（HSV → 四边形 → 深度分面 → PnP）
              └── /target_face + target_face TF
                    └── box_move / check_sim_vision
```

三个终端：

```bash
# 1) 仿真（视觉场景）
ros2 launch launch_pack arm_controller_test_sim.launch.py \
    mujoco_model:=$(ros2 pkg prefix arm_model)/share/arm_model/model_4dof/scene_vision.xml

# 2) 相机 TF + 检测
ros2 launch view view_sim.launch.py

# 3) 数值验收（退出码 0 = 通过）
ros2 run view check_sim_vision
```

一条龙视觉演示（跑完自动退出）：

```bash
ros2 launch launch_pack arm_task_vision_sim.launch.py
```

## 4 轴场景的几何（与 6 轴的根本差异）

4 轴是 **2R 平面臂**：joint1/joint2 都是俯仰，joint3 绕小臂自转，joint4 只转末端板。
末端 `link4` 原点的可达集基本是一个平面，实测：

| 量 | 数值 |
| --- | --- |
| 末端原点的 y 带 | −0.0126 ~ +0.0274（由 joint3 贡献，与 x/z 无关） |
| link4 工具沿 +z 的最远点 | 0.062 m（网格实测） |
| 工具尖的 y 可达 | −0.043 ~ +0.057 |
| y≈0 平面内末端可达区 | x ∈ [−0.82, 0.82]，z ∈ [−0.39, 0.87] |

由此推出场景参数（改任何一个都要重算整条链）：

- **可见面只能落在 y≈0.057~0.097**：`box_move.tool_offset` 取 0.07，末端目标 y=0.010；
- 箱体 0.35 立方、中心 (0.35, 0.183, 0.175)、绕 z 逆时针 45°，
  可抓面是 `-X'`（法线 (−0.707, −0.707, 0)），面心 (0.2265, 0.0595, 0.175)，
  末端目标 (0.177, 0.010, 0.175)；
- 相机在 (0.05, −0.55, 0.175) 斜看箱心，可抓面入射 28.9°，另一面 79.8°。
  **不要**把相机正对箱心（x=0.35）：两个面入射对称，追踪器实测会锁到 +x 侧那一面，
  而那一面要横穿箱体才能碰到（25 个随机 IK 种子里 0 组无碰撞解），
  `box_move` 直接以 0.2175 m 残差失败；
- 另一面只能作为分面点云存在（检测报 dual），**任务永远只抓 −X' 面**；
- `above_box` 取 (0.177, 0.010, 0.425) 的 IK 解：抬 25 cm 时手臂投影完全在箱体
  像框之外（15 cm 时 link3/link4 会压住箱体），且 `reset → above_box → 目标`
  两段插值全程无碰撞。

## 关键约束

- **相机位姿只有一个来源**：`model_4dof/scene_vision.xml` 的 `<camera pos/xyaxes>`；
  `view_sim.launch.py` 启动时解析它生成 TF。改相机只改 MJCF。
- 仿真和 `view_sim` 的 `scene_path` 必须指向**同一个文件**，否则 TF 与渲染不一致。
- 仿真里的 Python 检测节点**不要开 `use_sim_time`**：500 Hz `/clock` 会让 rclpy 吃掉一个核，
  检测循环从 30 Hz 掉到 1 Hz 量级（O13）。用图像 `header.stamp` 作时间基准。
- 图像订阅必须 `image_qos: reliable`：相机插件是 `depth=1` 的 reliable 发布，
  best-effort 会丢掉约 2/3 的帧，深度过期后分面退化为单面（O14）。
- `TargetFace` 与 TF 的时间戳新鲜度会检查；仿真里 `task_runner` 必须带 `use_sim_time:=true`。

## 目标检测参数

HSV 阈值、最小面积、核大小、深度分面参数、目标发布频率等都是 `red_quad_detector` 的参数。
默认目标：边长 0.35 m 的红色立方体，中心 (0.35, 0.183, 0.175)，相机 (0.05, −0.55, 0.175)。

`check_sim_vision` 的真值由参数给出：`box_center` / `box_size` / `box_normals`
（每 3 个数一个外法线）/ `expected_mode`（single / dual / triple / auto）。
默认是 4 轴场景的两个侧面（dual）；换单面或三面场景只改这几个参数即可。

## 离线视觉基准（MuJoCo）

`src/view/tools/bench_sim.py` 在包内独立跑一套 MuJoCo 场景，不启动 ROS、不含机械臂：
0.35m 红箱、640×480、fovy 60°（fx 415.69），深度来自 `mujoco.Renderer`
（与相机插件同一条 znear/far 换算）。

覆盖 single/dual/triple 各 10 个随机种子 × clean/noisy = 60 帧；遮挡/截断各 5 帧
（noisy，仅诊断）。dual 的 seed 0 复刻现有 `scene_vision.xml` 的 0.79m / 主面约
28.9° 位姿，seed 5 是同距离对称 45°；triple 用远相机（箱心约 1.6–1.8m），
让三个面同时进 65° 入射。精度口径沿用 `check_sim_vision`：面心 20mm、法线 3°、
箱心 15mm、边长 25mm，按均值判定。

```bash
cd src/view
python3 tools/bench_sim.py
```

输出 `out/bench/summary.md`、`frames.csv`、`summary.json`、`fail/`。

2026-11-21 结果：

- clean PASS：single 面心 1.01mm；dual 1.52mm / 箱心 2.91mm / 边长最大轴 12.9mm；
  triple 3.34mm / 3.08mm / 7.8mm。
- noisy FAIL：dual 面心 45.98mm、箱体三轴 348.2/540.0/453.7mm；原因是深度边缘飞点
  被计入侧面点云，`view` 的点云没有飞点过滤。single/triple 的 noisy 仍 PASS。
- 遮挡/截断各 5/5 仍出目标，面心 50.3 / 79.6mm，说明当前没有“不可抓就拒绝”的契约。
- 速度：`detect + sample_from_detection` 中位数 12.4ms（约 81 FPS）。
