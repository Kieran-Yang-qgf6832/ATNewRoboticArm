# 03 视觉链路

## 仿真链路

```
scene_vision.xml（固定深度相机 + 红色目标箱）
  └── CameraPlugin → /vision_camera/{color, depth, camera_info}
        └── view/red_quad_detector（HSV → 四边形 → 深度分面 → PnP）
              └── /target_face + target_face TF
                    └── box_move / check_sim_vision
```

三个终端：

```bash
# 1) 仿真（视觉场景）
ros2 launch launch_pack arm_controller_test_sim.launch.py \
    mujoco_model:=$(ros2 pkg prefix arm_model)/share/arm_model/model/scene_vision.xml

# 2) 相机 TF + 检测
ros2 launch view view_sim.launch.py

# 3) 数值验收（退出码 0 = 通过）
ros2 run view check_sim_vision
```

一条龙视觉演示：

```bash
ros2 launch launch_pack arm_task_vision_sim.launch.py
```

## 关键约束

- **相机位姿只有一个来源**：`scene_vision.xml` 的 `<camera pos/xyaxes>`；
  `view_sim.launch.py` 启动时解析它生成 TF。改相机只改 MJCF。
- 仿真和 `view_sim` 的 `scene_path` 必须指向**同一个文件**，否则 TF 与渲染不一致。
- 仿真里的 Python 检测节点**不要开 `use_sim_time`**：500 Hz `/clock` 会让 rclpy 吃掉一个核，
  检测循环从 30 Hz 掉到 1 Hz 量级（O13）。用图像 `header.stamp` 作时间基准。
- 图像订阅必须 `image_qos: reliable`：相机插件是 `depth=1` 的 reliable 发布，
  best-effort 会丢掉约 2/3 的帧，深度过期后分面退化为单面（O14）。
- `TargetFace` 与 TF 的时间戳新鲜度会检查；仿真里 `task_runner` 必须带 `use_sim_time:=true`。

## 目标检测参数

HSV 阈值、最小面积、核大小、深度分面参数、目标发布频率等都是 `red_quad_detector` 的参数。
默认目标：边长 0.35 m 的红色立方体，抬高标准场景箱体/相机 z=0.6。
