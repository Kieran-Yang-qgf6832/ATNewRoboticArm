# 08 开发约定

## 分层

```
ArmSolve → IKSolver → ModelBase + TaskMapping
```

- `ModelBase`（`ModelFromURDF`，Pinocchio）负责 FK、几何雅可比、RNEA、关节限位；
- `TaskMapping`（`Default6DofTaskSpaceMapping`）负责任务空间语义与投影；
- `IKSolver` 用信赖域 + LM，返回 `Converged` / `Unreachable` / `Failed`；不可达目标在下发前拒绝；
- 多路点用 C³ 七次 Bezier，1..8 个用户路点，全局时间尺度；
- 修改任务空间时**同步检查** `position_map()` 与 `jacobian_map()`（O5 的教训）。

## 控制器侧实时约束

`ArmController::update()` 是 500 Hz 实时路径，FSM 的 `enter()/run()/check_switch()/exit()`
都可能被间接调用：

- **禁止**调用 `get_parameter()` 等 ROS 参数读写；
- **禁止**动态内存：不能构造临时 `std::vector`，不能 `resize/reserve/assign/push_back`；
- FSM 内需要的内存只能在构造函数或控制器初始化阶段申请；
- `enter()` 只重置标量、拷贝到预分配 buffer、切换标志位；
- 运行时可更新的数组参数长度不得超过初始化时的关节数。

任务层运行在普通 ROS 节点线程，允许阻塞服务调用与内存分配。

## 参数声明

新增控制器参数必须：

1. 在 `ArmController::on_init` 里 `auto_declare`；
2. 同步更新 `ros2_controller.yaml`（实机差异写 `ros2_controller_real.yaml`）；
3. 在构造期读取，并在日志里打印实际生效值。

未声明的键会被**静默忽略**并取默认值，写错参数名不会有任何提示（C6）。

## 控制器接口

修改控制器接口时同步检查三处：

- controller YAML（`src/launch_pack/config/ros2_controller.yaml`）；
- URDF 的 `<ros2_control>` 接口标签；
- 插件 XML（`arm_ctrl_plugin.xml` / `sim_pid_plugin.xml` / `arm_real_plugin.xml`）。

## 实机约束

实机只有 5 个自由度（joint6 无电机、机械锁死），`task_dim=5`；固件没有指令看门狗，
拔线不会停机（R5）。涉及实机路径的开发先读
[实机首次运行与标定](04-实机首次运行与标定.md) 的 Phase 3.5 与附录 C。

  `bugs|adr|changelog` 条目都被索引，退出码非 0 就说明有断链或漏索引；
- **同步时机是“任务收尾”**：一次改动交付/验收前对照变更表同步一次，不要每次编辑都写、
  也不要拖到定期巡检。完整矩阵固化在 `.codebuddy/rules/doc-sync/RULE.mdc`
  （CodeBuddy 每个会话自动注入）；`CLAUDE.md` 的「任务收尾」是同一套规则的摘要，
  供 Claude Code 使用。两者读者不同，不是重复副本；
- 本节是开发约定的权威版本，`CLAUDE.md` 只保留 6 条禁令与导航。

## 已知命名债务

- `Paramter` 是 `Parameter` 的历史拼写（`lib/paramter_identify/`、`ParamterIdentify`）；
- `idel` 是 `idle` 的历史拼写，且是外部参数契约（`exp_state=idel`），改名会破坏命令。

改名前先评估兼容性；不要在其他改动里顺手重命名。
