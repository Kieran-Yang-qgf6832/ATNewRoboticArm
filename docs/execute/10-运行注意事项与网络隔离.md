# 运行注意事项与网络隔离

> 两条必须在**启动之前**确认的约定：
> 1. 同一台机器上，同一时刻只能有**一个** `controller_manager` 控制这台臂；
> 2. 本机的 ROS 2 通信**不要扩散到局域网**，也不要接收局域网里别人的节点。
>
> 背景与故障复现见 [O25](../bugs/2026-11-16/2159-spawner失败后launch继续运行.md)。

---

## 1. 单实例：同一时刻只能有一个控制者

### 1.1 为什么

`controller_manager` 的服务名固定为 `/controller_manager/*`。同 domain 里有两个实例时：

- spawner 的 `list_controllers` 被其中一个应答（“控制器已加载”），
  `configure` 落到另一个（“没有这个控制器”）——两个 spawner 都以 1 退出；
- `/joint_states`、`/arm_controller/*` 会有两个发布者，数值来回跳；
- `ros2 control list_controllers` 时好时坏（请求随机落到其中一个进程）。

这不是“两个线程抢锁”，而是两个进程各有一套同名端点，**杀线程没有用**。

### 1.2 启动前检查（每条 launch 都做）

```bash
# 1) 图里是否已有同名节点。必须加 --no-daemon：默认走 daemon 缓存，会显示已经退出的幽灵节点
ros2 node list --no-daemon | grep -c '^/controller_manager$'   # 期望 0

# 2) 真正数进程：同名节点在 ros2 node list 里会合并成一行，看不出重复
ps -o pid= -C ros2_control_node | wc -l                       # 期望 0
```

两条都是 0 再启动。`arm_real.launch.py` 已内置第 1 条检查：有残留时只打印
`[拒绝启动]` 并退出，不启动任何节点；spawner 失败也会立即 `Shutdown`。

### 1.3 正确的停止方式

| 方式 | 说明 |
| --- | --- |
| 前台 `Ctrl-C`，等 launch 打印 shutdown 完成 | 推荐。`ros2 launch` 会把信号转发给全部子进程 |
| `systemd-run --user --scope --unit=arm-real ros2 launch ...` + `systemctl --user stop arm-real` | 后台运行推荐，停止时整组进程一起收 |
| `kill -INT <ros2_control_node 的 pid>` | 只清理残留进程时用，pid 从 `ps -C ros2_control_node` 取 |
| ✗ 只杀 `launch` 父进程 / `pkill -f arm_real.launch.py` | 子进程会脱管，正是残留 manager 的来源 |

### 1.4 症状对照

| 日志 / 现象 | 含义 | 处理 |
| --- | --- | --- |
| `[拒绝启动] 检测到已有 /controller_manager 在运行` | 有残留进程 | `ps -C ros2_control_node` 找到 pid，`kill -INT` |
| `Controller already loaded` + `no controller with this name exists` | 两个 manager 抢服务（旧版 launch 的表现） | 同上 |
| `ros2 control list_controllers` 时而成功时而超时 | 同上 | 同上 |
| `/joint_states` 在两个值之间跳、RViz 抖动 | 两个 broadcaster 同名话题 | 同上 |
| `task_runner` 报“到位，最大关节误差 0.0000 rad”但实物没动 | `loopback=true`，或命令被旧进程执行 | 看日志 `loopback=false`；查进程 |

### 1.5 需要并行时：隔离名字或 domain

- **domain 隔离（最省事）**：`ROS_DOMAIN_ID=42` 起实机，`ROS_DOMAIN_ID=43` 起仿真，两边互不可见。
- **namespace 隔离**：`ros2_control_node` 加 `namespace`，spawner 的 `--controller-manager`
  同步改成 `/arm_a/controller_manager`；只改一边等于没改，spawner 仍会去找根命名空间的同名服务。
- **进程级独占锁（可选加固，当前未实现）**：在 `ArmRealInterfaces::on_configure` 里对
  `/dev/shm/arm_real_hw.lock` 做 `flock(LOCK_EX | LOCK_NB)`，抢不到就返回 ERROR。
  `loopback` 也要加锁——两个 loopback 实例争的是同一组话题，不是 USB。
  进程崩溃时内核自动释放，不会留死锁。

## 2. 局域网隔离：把 ROS 2 通信限制在本机

### 2.1 为什么

ROS 2 默认（Fast DDS，`ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET`）会跨机器发现同 domain 的所有节点。
实验室里别人的 `/joint_states`、`/robot_description`、`/controller_manager` 都可能进来：
`robot_state_publisher` 串扰导致加载错模型的问题已经出现过（见
[robot_description 话题串扰](../bugs/2026-10-10/1029-robot_description话题串扰.md)）。

### 2.2 推荐配置（写进 `~/.bashrc`）

```bash
# ROS 2：本机调试，避免和局域网内其他机器串话
export ROS_DOMAIN_ID=42
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
```

- `ROS_DOMAIN_ID` 取 0~101；默认 0 最容易和别人撞，团队约定一个固定值；
- `ROS_AUTOMATIC_DISCOVERY_RANGE` 取值 `SUBNET`（默认）/ `LOCALHOST` / `OFF`；
- 旧变量 `ROS_LOCALHOST_ONLY=1` 仍可用，但 Jazzy 起已弃用，优先用上面这个；
- **同一台机器的所有终端必须一致**，否则 `ros2 topic list` 互相看不见；
- 改完 domain 后执行一次 `ros2 daemon stop`，再验证。

### 2.3 验证

```bash
echo "domain=$ROS_DOMAIN_ID range=$ROS_AUTOMATIC_DISCOVERY_RANGE rmw=${RMW_IMPLEMENTATION:-默认 fastrtps}"
ros2 node list --no-daemon        # 只应出现本机自己的节点
```

跨机确认：在局域网中另一台机器上用**同一个** `ROS_DOMAIN_ID` 执行 `ros2 node list`，
看不到本机节点即隔离成功。

### 2.4 多机联调时临时打开

```bash
# 方式一：放宽到整个子网（两边同 domain）
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET

# 方式二：只连指定机器，不用多播
export ROS_AUTOMATIC_DISCOVERY_RANGE=OFF
export ROS_STATIC_PEERS=192.168.1.20
```

只在需要的那次终端里改，不要写进 `~/.bashrc`。

### 2.5 使用 CycloneDDS 时

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI='<CycloneDDS><Domain><General><Interfaces><NetworkInterface name="lo"/></Interfaces></General></Domain></CycloneDDS>'
```

`NetworkInterface name="lo"` 表示只绑回环；不设置时 CycloneDDS 仍会走默认网卡。

### 2.6 这不是安全边界

DDS 没有鉴权和加密。domain 与 `LOCALHOST` 只能减少误连，不能阻止同机器/同子网内
有意加入的节点；不要把“ROS 2 隔离”当成访问控制。

## 3. 启动前速查

```bash
# 1) 环境
echo "domain=$ROS_DOMAIN_ID range=$ROS_AUTOMATIC_DISCOVERY_RANGE"

# 2) 没有残留控制者
ros2 node list --no-daemon | grep -c '^/controller_manager$'
ps -o pid= -C ros2_control_node | wc -l

# 3) 实机启动（不要加 loopback），必须看到这三行
ros2 launch launch_pack arm_real.launch.py
#   Configured ArmRealInterfaces for 4 joints, 4 motors (loopback=false, ...)
#   Configured and activated arm_controller
#   arm_controller 已激活
```
