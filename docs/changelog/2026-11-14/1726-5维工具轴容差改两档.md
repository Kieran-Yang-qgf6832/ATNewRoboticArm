# 变更：5 维工具轴容差改为「收敛 1° / 通过 10°」

- 日期：2026-11-14 17:26
- 类型：兼容性 / 行为变化
- 相关：[02 仿真运行](../../execute/02-仿真运行.md)、[07 离线工具与排错](../../execute/07-离线工具与排错.md)、[验证记录](../../bugs/2026-11-14/1710-5维放宽容差的可达性验证.md)

## 背景

`pos_move`（带 `orientation`）与 `box_move` 的 5 维（位置 + 工具 z 轴）目标只有一个角容差
`pos_move_axis_tolerance_deg = 1°`，同时充当「IK 迭代什么时候停」和「任务层验收」。目标贴着
关节限位时，1° 达不到就整条轨迹被预检拒绝，`box_move` 再退化成完全不约束姿态的
position-only——比「差 3° 但工具方向仍可控」更差。

## 变更

- 控制器新增 `pos_move_axis_converge_tolerance_deg`（默认 1°）：迭代**停止**判据，进入即停。
- `pos_move_axis_tolerance_deg` 语义改为**通过**判据，默认 1° → **10°**：
  跑完仍未进入收敛判据时用它裁决是否算成功。
- `IKSolver::set_solve_options()` 增加第 4 个参数（工具轴通过容差，默认 0 = 与收敛判据相同，
  旧调用行为不变）；`SolveResult::Converged` 因此可能是「放宽解」，
  新增 `last_used_relaxed_axis()` 供诊断。
- 任务层 `position_move.axis_tolerance_deg` 与两个代码默认值同步改为 10°；
  位置判据（默认 5 mm，`pos_move_tolerance` 1 mm）不变。
- `box_move` 的 position-only 回退逻辑不变，只是触发条件自然变成「连 10° 都不可达」。
- `box_move` 结束时多打印一行工具尖端偏移 `2·tool_offset·sin(θ/2)`（只读，不参与判据）：
  10° 在 `tool_offset=0.039 m` 下约 6.8 mm，已大于 5 mm 位置容差。
- 预检若靠放宽判据通过，控制器打 WARN：
  `5D target accepted with the relaxed tool-axis tolerance: nearest reachable axis error ...`。
- `ik_solve` 增加 `--accept-axis <deg>`（默认 10），用于严格/放宽的 A/B。
- `tasks.yaml` 新增 `pos_axis_limit_probe`（观测用例，**不覆盖放宽分支**）与对应目标点。

## 影响与迁移

- **行为变化**：5 维轨迹允许以最多 10° 的工具轴误差合法结束；能对齐的目标仍按 1° 停，
  精度不退化。若要保持旧行为，把 `pos_move_axis_tolerance_deg` 与
  `position_move.axis_tolerance_deg` 都改回 1（此时两档相同，等价于旧逻辑）。
- 两档写反（收敛 > 通过）会被 clamp 到通过值并打 WARN。
- 参数仍在构造期读取，改 yaml 必须重启控制器（C6）。
- `real_compat_box` 的验收判据仍为 ≤1°，与运行时 10° 是两个口径（见 [05 任务层](../../execute/05-任务层与序列.md)）。

## 验证

- 离线 A/B（`ik_solve --axis`，目标位置残余 2.2e-5 m、轴残余 1.875°，初值 joint5=0.4）：
  默认档 `Converged` + `relaxed_accept = yes`；`--accept-axis 1` 同一残余下 `Unreachable`，
  两次 `ik_err` 完全相同（3.272270e-02）。
- 仿真 `pos_axis_limit_probe`：退出码 0，`cart constraint: ... axis_tolerance=10 deg (converge 1 deg)`；
  实测 tool-axis error 0.11°、位置残余 2.3 mm。**未触发放宽分支**——6 自由度下这条目标
  其实可达，原因见验证记录。
