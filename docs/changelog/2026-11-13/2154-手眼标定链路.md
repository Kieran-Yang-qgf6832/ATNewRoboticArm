# 变更：手眼标定链路（eye_on_base）

- 日期：2026-11-13 21:54
- 类型：功能
- 相关：[09 手眼标定](../../execute/09-手眼标定.md)

## 背景

视觉链路一直在用仿真里的占位外参，实机没有可用的 `base_link -> camera_link`。
需要一条能自己闭环的手眼标定流程：标靶检测 → easy_handeye2 采样 → 外参发布 → 验收。

标靶是 calib.io 的 ChArUco 200×150（11×8 格、15/11 mm、`DICT_4X4_50`）。
实测这张板的白格相位与 OpenCV 内置 `CharucoBoard` 模板相反，直接用内置板定义会得到
160 px 量级的重投影误差，因此版面角点按实物自己生成。

## 变更

### 功能

- 新增 `view/calib_board.py`（`calib_board_detector`）：
  - 按实物布局生成 44 个 marker 的三维角点，176 个角点 `solvePnP(SOLVEPNP_IPPE)`；
  - `CORNER_REFINE_SUBPIX` 亚像素精化；
  - 连续 3 帧位姿一致（平移 < 5 mm、旋转 < 1°）才广播 TF，防止误检污染采样；
  - 动态 TF `<彩色帧> -> calib_board`，时间戳用图像 stamp，丢失即不发。
- 新增 `view/launch/calib.launch.py`：相机 + 检测 + easy_handeye2 采样界面一条命令。
- 新增 `view/check_handeye.py`（`check_handeye`）：多姿态下板位姿恒定度验收，自动分组。
- 新增 `launch_pack/launch/handeye.launch.py`：读项目 `.ros/easy_handeye2/<name>.calib`
  发静态 TF，绕开 `handeye_publisher` 的 `~/.ros2` 硬编码路径。
- `view` 包增加 `easy_handeye2` 依赖与两个入口点。

### 文档

- 新增 `docs/execute/09-手眼标定.md`（参数、采样、导出、验收、已知坑）；
- 启动章节按「两个终端，先机械臂后视觉」写：`view calib.launch.py` **不含**机器人控制节点，
  缺 `base_link -> link6` 时采样不可用；
- 记录 [O17](../../bugs/2026-11-14/1049-rqt采样窗口不显示.md)：缺 TF 时 rqt 窗口根本不会出现
  （服务在 TF 就绪前不创建，客户端无超时等待），不是 rqt 崩溃。

## 影响与迁移

- 现有 `red_quad_detector` 与 `box_move` 未改动；
- 标定结果落在 `.ros/`（已 gitignore），换机器需重标；
- 接进业务链前必须重算箱体粗定位点。

## 验证

- 版面几何与门禁：`pytest src/view/test/test_calib_board.py`，9 项通过；
- 用 PDF 200 dpi 渲染图端到端解算：44 个 marker、RMS 0.703 px、
  `tvec = (-82.6, -60.1, 501.1) mm`（与 165×120 板面的左上角位置一致）；
- `ros2 launch view calib.launch.py start_camera:=false` 起齐检测节点、
  dummy TF 与 `handeye_server`，参数读作 `base_link -> link6` / `camera_link -> calib_board`；
- `ros2 launch launch_pack handeye.launch.py calib_file:=<tmp>` 正确发布静态 TF；
- `python3 docs/tools/check_docs.py` 通过（链接与索引齐备）。
