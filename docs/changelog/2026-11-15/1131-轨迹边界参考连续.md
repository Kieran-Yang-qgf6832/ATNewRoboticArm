# 变更：轨迹段边界的参考连续性 + 力矩前馈限速

- 日期：2026-11-15 11:31
- 类型：行为变化 / 新参数
- 相关：[O19](../../bugs/2026-11-15/0913-轨迹段边界跳动.md)、
  [ADR-20261115-1131](../../adr/2026-11-15/1131-参考连续性与力矩限速.md)

## 背景

逐段下发轨迹时每段首末都会跳一下、实机还伴随一声闷响（O19）。三条机制：段末把保持命令
锁存到实测、段首用发送时刻的实测做首点、保持与轨迹的力矩不是同一个工作点。

## 变更

- **段末锁存改为「最后一帧命令」**：`arm_joint_traj`、`arm_cart_traj` 与两条多路点路径
  在轨迹结束时冻结本周期刚写下的命令，不再取实测。`idel` / `reset` / 故障保持不变。
- **段首重定基**：`arm_joint_traj` 的首点、`arm_joint_waypoints` 的首节点改取上一帧命令，
  发布者给的起点只当提示。笛卡尔路径的段首未改。
- **新参数 `torque_slew_rate`**（N·m/s，0 = 关闭，默认 300）：`ArmController::update()`
  在写 effort 接口前做斜率限制，故障保持路径同样过限速；`measure` / `teach_pendant`
  豁免（它们自己产生前馈）。两份控制器 YAML 都写了 300。
- **两条只报告的 WARN**：段末 `|轨迹终点 − 实测| > 0.1 rad`、段首
  `|首发点 − 上一帧命令| > 0.1 rad`。

## 影响与迁移

- 逐段运动的段末不再有位置台阶；代价是段末会有一段回弹把动态拖拽的偏差拉回终点。
- 实机 `joint_command.effort` 在状态切换处不再是一帧 0 ↔ 20 N·m，而是 300 N·m/s 的斜坡
  （100 Hz 下 21 N·m 约 70 ms）。想对照旧行为把 `torque_slew_rate` 设成 0 即可。
- `torque_slew_rate` 可热更新（`ros2 param set /arm_controller torque_slew_rate`）；
  其余控制器参数仍按 C6，构造期读取。
- 没有任何话题/消息结构变化；`~/joint_command` 记录的就是限速后真正下发的值。

## 验证

仿真 bag `.ros/ros2bags/arm_sim_20261115-112444`：段边界单帧位置跳变 0.0000–0.0002 rad
（判据 ≤ 0.01），单帧力矩跳变 3.000 N·m / 100 Hz = 300 N·m/s（判据 ≤ 300），
段末 0.305 rad 的偏差 1 s 内收敛到 0.012 rad（判据 ≤ 0.02）。细节见
[O19 § 验证](../../bugs/2026-11-15/0913-轨迹段边界跳动.md)。实机待复测。
