## 变化

1. 新增 `src/view/tools/sim_scene.py`：独立 MuJoCo 场景（0.35m 红箱、无机械臂、
   640×480、fovy 60°→fx 415.69），参数化相机位姿、真值面/箱体、RealSense 级噪声。
2. 新增 `src/view/tools/bench_sim.py`：single/dual/triple 各 10 种子 × clean/noisy
   = 60 帧；遮挡/截断各 5 帧（noisy，仅诊断）；精度口径沿用 `check_sim_vision`
   的容差（面心 20mm、法线 3°、箱心 15mm、边长 25mm，按均值判定），并测
   `detect + sample_from_detection` 耗时、cProfile 分模块；报告写 `out/bench/`。
3. `src/view/.gitignore` 忽略 `out/`；`03 视觉链路` 增加“离线视觉基准”一节，
   `07 离线工具与排错` 增加命令索引。

## 结果（2026-11-21 本机）

- clean 一组 PASS：
  - single 面心 1.01mm；
  - dual 面心 1.52mm、箱心 2.91mm、边长最大轴 12.9mm；
  - triple 面心 3.34mm、箱心 3.08mm、边长最大轴 7.8mm。
- noisy 一组 FAIL（仅 dual）：
  - dual 面心 45.98mm，箱体三轴 348.2/540.0/453.7mm；
  - 原因是深度边缘飞点被计入侧面点云，`view` 的点云没有 `fly_pixel_mask` 过滤；
    纯高斯深度噪声下箱体尺寸仍正常（351×341×363mm）；
  - single 与 triple 的 noisy 仍 PASS（面心 1.06 / 5.87mm）。
- 遮挡/截断诊断：各 5/5 仍出目标，面心均值 50.3 / 79.6mm，当前没有拒绝契约。
- 速度：`detect + sample_from_detection` 中位数 12.4ms（约 81 FPS）。
- dual 的 seed 0 复刻现有 `scene_vision.xml` 的 0.79m / 主面约 28.9° 位姿；
  triple 用远相机（箱心约 1.6–1.8m），让三个面同时进 65° 入射。

## 兼容性

- 不修改 `view` 检测代码、`scene_vision.xml` 或 ROS 链路；实时查看仍用
  `ros2 launch view view_sim.launch.py`。
- 基准依赖 MuJoCo 无头渲染（`MUJOCO_GL=egl`）；triple 是远距能力测试，
  不代表 4 轴部署位（部署为 0.79m 的 dual）。
- single 在 `check_sim_vision` 里会因 `has_box=False` 被过滤，本基准直接评估
  面心/法线，因此 single 的数值不能与现有验收逐项对齐。
