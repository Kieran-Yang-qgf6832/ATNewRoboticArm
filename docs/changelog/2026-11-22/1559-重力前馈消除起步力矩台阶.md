## 背景

实机 `gravity_compensation: false`，保持态写 0 力矩、轨迹态写完整 RNEA，于是每条轨迹的
**开始与结束**都是一次 `0 ↔ τ_g` 的二值切换：`arm_real_20261121-203145` 里 9 次事件，
每次 0 ↔ 3.4/5.7/6.5 N·m、按 300 N·m/s 限速走 2–3 帧（20–30 ms）。位置与速度命令本身是连续的
（单帧 Δv ≤ 0.007 rad/s），所以现象就是「位置、速度都不动，力矩却跳」（O19 的第三因、O21）。

根因不是「缺一段斜坡」，而是**两条路径的力矩不在同一工作点**；`torque_slew_rate` 只是把阶跃摊成
20–30 ms。

## 变更

1. **`idel` 一次性力矩脉冲通道**（`test_torque_joint` / `test_torque_value` / `test_torque_duration`）：
   默认关闭，只在 `idel` 生效，`|τ| ≤ 5 N·m`、`≤ 0.5 s`、到点自动归零、请求 30 s 未被消费即作废。
   用于确认**下行**力矩通道的符号（位移方向只由下行决定，不受上行 `effort` 反号影响）。
2. **实机开启重力前馈**：`src/launch_pack/config/ros2_controller_real.yaml` 的
   `gravity_compensation` 由 `false` 改为 `true`，`gravity_compensation_scale` 由 `0.1` 经 0.5 提到 **1.0**。
   `scale` 只乘保持路径，台阶 = `(1 − scale)·τ_g`，中间档不消台阶，必须 1.0。
3. **文档**：`docs/execute/04` 新增 5.5「标定重力力矩方向」（含完整命令、判据、记录表），
   `docs/execute/07` 的脉冲节收敛为工具语义；`joint_calibration.yaml` 头部补第三条符号的说明。

## 影响与迁移

- 实机保持期间不再零力矩：`command.effort` = RNEA 重力项，静差从 τ/k 变为残余误差。
- 轨迹起步/停止的力矩台阶消失（见验证）；`torque_slew_rate = 300` 保留，作为故障保持、
  模式切换等其它突发的兜底，不再被轨迹边界触发。
- **参数只在状态机构造时读一次**：改完必须重启 `arm_real.launch.py`，运行中 `ros2 param set`
  会被接受但不生效；启动日志有 `gravity_compensation=true scale=1.000 (param found=yes)` 可核对。
- **回滚**：把 `gravity_compensation` 改回 `false`（或 scale 回到 0.5）再重启，行为即回到今天上午。
- joint5 未做脉冲试验，但该位形重力项约 0.0002 N·m，开启后影响可忽略。
- joint2 的上行 `effort` 与 RNEA 反号仍在（下行已确认同号）：只影响参数辨识与诊断读数，
  不影响控制，记在 O21 里待处理。
- 笛卡尔链（`pos_move` / `box_move`）仍没有首点 rebase、`command.velocity` 恒 0，
  实机 `allow_constrained_traj: false` 时进不去；打开前必须处理（ADR 的「未覆盖」）。
