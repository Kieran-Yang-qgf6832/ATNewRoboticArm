# 跨分支同步

`4dof/main` 与 `jazzy/main` 长期并行：前者是 4 自由度硬件主线，后者是 6 自由度主线。
两个分支**不做 merge**，新功能从 `jazzy/main` 逐个 cherry-pick 到 `4dof/main`。

本目录只承担一个职责：**记录哪些提交已经挑过来、哪些是故意跳过的、哪些还欠着**。
缺陷、决策、操作步骤分别写在 [`bugs/`](../bugs/README.md)、[`adr/`](../adr/README.md)、
[`execute/`](../execute/README.md)，这里不重复。

| 文档 | 内容 |
| --- | --- |
| [同步记录.md](同步记录.md) | 提交级台账：每个 `jazzy/main` 提交在 4 轴分支上的去向与理由 |
| [4轴差异.md](4轴差异.md) | 4 轴相对 6 轴的能力边界，以及由此产生的代码与文档差异 |
| [2026-11-15-首次迁移.md](2026-11-15-首次迁移.md) | 第一次迁移的操作记录：做了什么、冲突怎么解、验收数据、遗留缺口 |

## 维护规则

- 每挑一个提交，在同步记录表里把状态从「待挑」改成「已挑」并写上新的提交号；
- 决定跳过时必须写理由——半年后光看 `git log` 分不清「跳过」和「漏了」；
- 移植工作量大的提交（如 `052494b`）记为「待移植」，不要留空。
