# ADR-20261115-1131：参考连续性与力矩限速

- 状态：已采纳
- 日期：2026-11-15 11:31
- 相关：[O19 轨迹段边界跳动](../../bugs/2026-11-15/0913-轨迹段边界跳动.md)、
  [设计约束 C4](../2026-11-13/1928-设计约束C1-C10.md)、
  [02 仿真运行](../../execute/02-仿真运行.md)、[08 开发约定](../../execute/08-开发约定.md)

## 背景

逐段下发轨迹时，每段首末都会「跳」一下（O19）。bag 实测把它拆成三件事：

1. 段末把保持命令锁存到**实测**位置，锁存的那一帧命令等于瞬移了当时的跟踪误差
   （O19 bag 里 joint4 +0.343 rad）；
2. 段首用**发送时刻的实测**做首点，与控制器的保持命令差一个等待期的塌陷（实机约 0.09 rad）；
3. 保持路径与轨迹路径的力矩来源不同（保持是重力前馈，轨迹是完整 RNEA），实机上
   是一帧 **0 ↔ 21 N·m** 的阶跃，而固件把这路力矩直接叠到速度环输出上，不限幅也不斜坡。

进一步量化后修正了一个直觉：那 0.343 rad 不是稳态静差，而是 joint3 快速摆动期间把
joint2/joint4/joint6 拖出来的动态偏差，段末前 0.25 s 已经开始回弹。所以「锁存终点、
让伺服拉回」不会留下永久静差。

## 决策

**参考只能在命令之间连续演化；实测只在没有参考可用时（`enter()`）进入参考。**

- 轨迹**结束**时锁存本周期刚写下的命令（`latch_command_position()`），不锁实测；
  `idel` / `reset` / 故障保持仍锁实测——「停」的语义就是停在当前姿态。
- **关节空间**轨迹的段首用上一帧命令覆盖首点；发布者的 `wp0` 被当作提示，不是参考。
  偏差超 0.1 rad 打 WARN。
- 力矩前馈在 `ArmController::update()` 出口做斜率限制（`torque_slew_rate`，默认
  300 N·m/s，0 = 关闭），故障保持路径同样过限速；`measure` / `teach_pendant` 豁免。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 段末淡出到锁存的实测 | 不跳也不拉回，但会把 0.2–0.34 rad 的姿态误差固化进保持点，下一段又从那里起步 |
| 段末锁存实测后再限速爬回终点 | 无台阶且最终到位，但段末有数秒缓慢爬行，还多一个过渡状态与参数 |
| 段末维持锁存实测，只削力矩 | 位置参考仍是单帧台阶，实机那一声闷响还在 |
| 段首用 0.2 s 偏移淡入 | 过渡更软，但要多一个参数并改写轨迹前段形状；覆盖首点零参数且形状不变 |
| 段首由任务层改用 `~/joint_command` | 让任务层也承担连续性，且任何其它发布者仍能打出台阶 |
| 限速放在 `ArmRealInterfaces::write()` | 最贴近「固件不限幅」的事实，但仿真验收看不到，`~/joint_command` 也不再是真正下发的值 |
| 限速覆盖 measure / teach | 激励轨迹是 10 s 周期 3 次谐波、幅值 30 N·m 量级，力矩变化率可到 170 N·m/s，削峰等于改写计划轨迹，污染辨识数据（O8–O12） |

## 后果

- 段末会有一段可见的回弹（把动态拖拽的偏差拉回终点），不再是「停就得住」。
- 保持力矩在`重力补偿关闭 + 轨迹`之间切换时按斜坡爬升/下降，实机 `gravity_compensation`
  仍然关着（RNEA 符号与幅值未上机核实），斜坡是对这一缺陷的兜底而不是替代。
- 笛卡尔路径的**段首**没有覆盖（首点是位姿、逐周期用实测做 IK 初值），它的下垂台阶仍在。
- `torque_slew_rate` 是可热更新参数（单个 double）；其余控制器参数仍按 C6，构造期读取。

## 验证

见 [O19 § 验证](../../bugs/2026-11-15/0913-轨迹段边界跳动.md)：仿真段边界位置跳变
0.0000–0.0002 rad、力矩 300 N·m/s，段末 0.305 rad 的偏差 1 s 内收敛到 0.012 rad。
实机待复测。
