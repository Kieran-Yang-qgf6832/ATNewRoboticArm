# ADR-20261122-1007：用重力前馈消除起步/停车的力矩阶跃

- 状态：已采纳并落地（2026-11-22 实机 1.0 档验收通过：台阶 ≤0.06 N·m）
- 日期：2026-11-22 10:07
- 相关：`src/arm_controller/arm/arm_fsm.cpp`、`src/arm_controller/config/joint_calibration.yaml`、
  `src/launch_pack/config/ros2_controller_real.yaml`、[O21](../../bugs/2026-11-22/1007-保持与轨迹力矩交接仍是阶跃.md)、
  [ADR-20261115-1131](../2026-11-15/1131-参考连续性与力矩限速.md)

## 背景

目标（操作者口径）：**段内保持位置、速度、力矩的平滑，每次运动开始不要出现速度与力矩的跳变。**

`arm_real_20261121-203145` 的实测把问题收敛到一个点：

- 位置与速度指令已经连续——五次曲线、`v(0)=0`、首点 `rebase` 到上一帧命令，
  逐帧 `|Δq| / (|v|·dt)` 中位 1.00；
- 力矩不连续——保持路径写 0（`gravity_compensation: false`），轨迹路径写完整 RNEA，
  段首 0 → 6.55 N·m / 33 ms（joint2）、段末反向冲一下再归零；
- 观感上的「位置跳 5–10 mrad」「Δτ=6.003 N·m」都是 10 ms 发布拍频与一次 20 ms 控制周期的
  采样假象，不是控制问题。

O19 当时已识别出这条根因（「保持力矩与轨迹力矩不在同一工作点」），但选择了
`torque_slew_rate` 把阶跃摊成斜坡，并把「实机打开重力补偿」列为未采用方向——
理由是当时无法验证 RNEA 的符号与幅值。本次把这个前置条件补上。

## 决策

1. **结构解 = 保持态也带重力前馈**。只有让「保持」与「轨迹」两种状态的力矩处在同一量级，
   交接才是连续的；拉长斜坡或用延时启动都只是把台阶摊平或推后。
2. **先验符号，再开前馈**。`idel` 增加一次性力矩脉冲通道（`test_torque_joint` /
   `test_torque_value` / `test_torque_duration`，默认关闭、仅 idel 生效、`|τ| ≤ 5 N·m`、
   `≤ 0.5 s`、到点自动归零、请求 30 s 未消费自动作废）。
   - 试验：joint2 施加 **+2 N·m / 200 ms**（URDF 符号）；
   - 判据：`/joint_states` 的 q2 **增大** ⇒ 下行前馈符号正确；
   - 依据：固件位置环等效刚度实测 ≈ 2600 N·m/rad（4.2 N·m ↔ 1.6 mrad），2 N·m 能推开约
     0.8 mrad，是位置抖动（±0.3 mrad）的 2–3 倍；0.5 N·m 只有 0.19 mrad，读不出方向。
   - 该试验只测**下行**通道；上行 `effort` 的 joint2 反号是另一件事（O21 现象 4），
     不影响臂往哪边走。
3. **scale 只走 0.5 → 1.0 两档**。0.5 用来确认保持静差随补偿单调下降（模型幅值验真），
   1.0 才是台阶真正消失的档。
4. **保留 `torque_slew_rate = 300`**。它是故障保持、模式切换等其它突发的兜底；
   台阶消失后它自然不再被触发。
5. **验收四项**（基线见 O21）：起步 Δτ ≤ 1 N·m；保持静差 ≤ 50% 基线；
   joint2 耦合漂移 p95 ≤ 50% 基线（29.2 → ≤ 15 mrad）；joint3 跟踪误差不恶化（5.84 mrad）。
6. **范围只到关节空间**。笛卡尔链（`pos_move` / `box_move`）的首点 rebase 与
   `command.velocity` 写入拆到下一次（理由见「未覆盖」）。
7. **文档顺序**：O21 + 本 ADR 先落，changelog 等实机试验数出来再补。

## 备选方案

- **只把力矩斜坡拉长（300 → 50–80 N·m/s）**：不需要相信模型，但 6.6 N·m 的台阶变成
  80–130 ms 斜坡，期间固件位置环要拉平差，跟踪误差变大；且治标。
- **段首预载 + 延后轨迹时钟**：每段开始前先写起点姿态的 RNEA，等力矩到稳态再启动轨迹时钟。
  轨迹形状不变，但每段多出 40–70 ms 静止，且依赖同一套模型——比方案 1 多一层机制，
  收益相同。
- **scale 从 0.1 起四档递进**：每档的起步台阶几乎不变（`(1−scale)·τ_g`），只在 1.0 消失，
  时间成本却翻倍。0.5 一档已足够暴露「模型反号」与「幅值偏大一倍」两类错误。
- **脉冲通过后直接 1.0**：少一次上下电，但幅值错误只能在 1.0 暴露（静差反号或缓慢自走），
  风险集中在那一次。
- **笛卡尔链同批改**：会把任务层、消息、FSM 三处变量混在一次变更里，而笛卡尔部分只能在
  仿真验证（实机 `allow_constrained_traj: false`）。

## 后果

- 起步/停车的力矩交接从 6.6 N·m 阶跃降到「惯性 + 科氏」的残余项：本 bag 里轨迹峰值
  6.61 N·m 对静态 6.56 N·m，残余约 0.05 N·m（<1%）。
- 保持态持续出力，因此**模型幅值错误会变成持续偏载**，必须在 0.5 档核实静差方向；
  scale=1 时若静差反号，说明 RNEA 幅值偏大，退回 0.5 并复核 URDF 质量参数。
- 生产代码里多出一条能直接下力的调试通道（三条约束：仅 idel、幅值/时长硬上限、
  请求 30 s 过期），需在 `docs/execute/07` 里写明用法与风险。
- `test_torque_*` 三个参数默认 0，YAML 里不出现即完全无效。

## 实施记录（2026-11-22）

- 脉冲通道：当天 10:07 落地，仿真验证通过（2 N·m 方波 0.190 s、越界写入被拒）。
- 符号试验：14:58 在实机逐关节做（bag `arm_real_20261122-145837`），**joint1–joint4 全部与 URDF
  同号**（2 N·m 打出 3–13 mrad），joint5 未测但重力项约 0.0002 N·m。
  → 决策里的「`torque_dir` 单独字段」**不再需要**，现有 `dir` 已能正确映射力矩通道；
  joint2 的反号只发生在上行 `effort` 上报（影响辨识/诊断，不影响控制）。
- 判据修正：必须取**脉冲持续期间**的位移，脉冲结束后的过冲反号会把方向读反
  （joint1 峰值 +8.4 mrad 后掉到 −5 mrad）。
- 档位：15:38 开 0.5，15:47 提到 **1.0**。实机实测（`arm_real_20261122-154728`，7 条轨迹）：
  轨迹起止最大单帧 Δτ 由 3.0 N·m 降到 **0.01–0.06 N·m**，保持段 `command.effort` 与 RNEA 逐项一致，
  静差 0.20 / 0.38 mrad（j2/j3，轻载位形）。模型幅值核对通过——若质量偏大，1.0 档会静差反号或自走。

## 未覆盖

- **笛卡尔链**：`pos_move` / `box_move` 没有首点 rebase，首点取发布时刻实测位姿，与锁存命令
  之差（本 bag 里 joint2 可到 29–33 mrad）会被 IK 在一个周期内吃掉，等效起步速度脉冲 ~3 rad/s，
  且 `command.velocity` 恒 0。必须在 `allow_constrained_traj` 打开前完成。
- **`measure` / `teach_pendant` 豁免**：力矩限速对这两个状态豁免，本次未复核它们的交接行为。
- **摩擦与背隙**：joint2 耦合漂移 29 mrad 里有多少来自重力未补偿、多少来自关节摩擦/
  背隙，本次不区分；脉冲通道可作为后续摩擦辨识的激励源。
