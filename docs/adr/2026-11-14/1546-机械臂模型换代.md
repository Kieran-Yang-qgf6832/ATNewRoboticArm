# ADR-20261114-1546：机械臂模型换代

- 状态：已采纳
- 日期：2026-11-14 15:46
- 相关：[实机首次运行与标定](../../execute/04-实机首次运行与标定.md)、[仿真运行](../../execute/02-仿真运行.md)、[参数辨识采用 FIGAROH + CMA-ES](../2026-10-13/1202-参数辨识采用FIGAROH与CMA-ES.md)

## 背景

实机机械臂换代，CAD 重新导出。旧一代模型的 `src/arm_model/model/` 自初始提交起就没动过，
其 link 帧、连杆长度与新一代 CAD 相差 20~80 mm（旧 joint3 x=0.52、joint4 x=0.436、
joint5 偏移 0.0776；新 joint3 x=0.5000、joint4 x=0.4934、joint5 偏移 0.0420），
零位末端位置相差 78 mm，已不能代表真机。

新一代 CAD 的原始导出（仓库根目录 `model/`）是 SolidWorks 直出格式，直接覆盖会让整条
仿真链路失效：

- 硬件插件写 `mujoco_ros2_control/MujocoSystem`（本仓库只注册 `MujocoSystemInterface`）；
- 没有 `mujoco_model` / `headless` 参数，MuJoCo 不知道加载哪个场景；
- 没有 `xmlns:xacro` 与 `hardware` 分支，实机链路 `arm_controller/ArmRealInterfaces` 消失；
- 没有 `acceleration` 状态接口，参数辨识依赖的真实关节加速度取不到；
- mesh 前缀是 `package://arm/`，本仓库没有名为 `arm` 的包。

## 决策

模型文件整体替换为新一代 CAD 导出，**工程脚手架保留**：URDF 仍带 xacro 四参数
（`headless` / `hardware` / `loopback` / `mujoco_model`）与 mujoco/real 双硬件分支、
六个关节的 `acceleration` 状态接口；mesh 前缀统一为 `package://arm_model/model/`。

数值层面一律采用新一代 CAD，只有下面两处刻意保旧：

| 项 | 取值 | 理由 |
| --- | --- | --- |
| `<limit effort>` | 50 N·m | 导出值 100 是 SolidWorks 默认值；`ros2_controller.yaml` 的 `measure_traj_torque_limit_rate: 0.6` 就是按 50 N·m 折算力矩门禁 |
| `scene.xml` 地面 | `contype=1 conaffinity=1` | 新导出是 `0/0`，机械臂可直接穿地，`measure_traj_ground_clearance` 与 [撞地污染辨识](../../bugs/2026-10-13/2226-激励轨迹撞地面污染辨识.md) 的防护会全部失效 |

其余非几何项按新导出：URDF/MJCF 的质量、质心、惯量、限位，MJCF 的 21 对自碰撞排除、
`ctrlrange ±100`、`joint6 damping=2.0`、`ee_site pos="0 0 0.05"`。

## 关键实现细节

- **轴方向**：joint2/joint3/joint4 的轴为 `0 0 -1`，与旧一代的 `0 0 1` 相反。关节变量的
  符号语义因此改变，旧 `tasks.yaml` 位形不再对应同一姿态。
- **joint5 不是纯自旋**：轴为 `-0.05715 0 -0.99837`，相对工具 z 倾斜 3.28°，是 CAD 原值，
  未做正交化。5 维任务里"绕工具轴投影"的前提要按倾斜后的实际轴重验。
- **自碰撞全排除**：新网格之间存在固有穿插（link3 与 link5 最多 2.6 mm），会在 joint4 上
  产生 0.2~0.8 N·m 虚假约束力矩，因此 MJCF 排除全部 21 对 contact，而不是旧的"只排相邻 6 对"。
- **`robotic_arm_real_compat.xml` 必须跟随主模型重生**：它只应比 `robotic_arm.xml` 多
  `motor6 gear=0`。本次按新主模型重新生成，没有沿用旧几何。
- **5 个场景变体保留**：`scene.xml` / `scene_vision.xml` / `scene_vision_raised.xml` /
  `scene_real_compat.xml` / `scene_vision_raised_real_compat.xml` 都是
  `<include file="robotic_arm.xml"/>`，主模型换新后自动跟到新几何，相机与箱体参数不动。

## 备选方案

- **整套照搬 `model/` 只补能启动的部分**：最贴 CAD，但力矩上限翻倍、地面碰撞关闭、
  实机分支缺失，等于把两条已知的防护与一条实机链路换掉，放弃。
- **只换 mesh 与外观**：风险最低，但新连杆长度、新限位、新惯量都不会生效，等于没换。
- **保留旧一代的辨识质量/惯量**：旧值是绑在旧 link 帧上的（质心坐标、惯量张量都以旧帧为
  基准），换帧后直接错位，混用比全换更容易出看不见的错。

## 影响与遗留

本次只替换模型文件，不改下游配置，因此以下数值仍是旧一代的，**使用时需要复核**：

- `src/tasks/config/tasks.yaml` 的 `joint_limits`、`tool_offset`、各序列关节角；
- `src/tasks/tools/waypoint_check.py` 的 `JOINT_NAMES` / `JOINT_LIMITS`；
- `src/arm_controller/config/joint_calibration.yaml`（实机零位与方向，需重新标定）；
- `src/launch_pack/config/ros2_controller.yaml` 的 `default_kp` / `default_kd` / 导纳参数，
  以及 `measure_end_effector_tool_offset: 0.07`（新 `ee_site` 已移到 0.05）；
- `src/FloBaRoID/` 下的辨识结果 URDF 基于旧一代模型，需重跑辨识。

另有两处 CAD 自带的不一致，未做修改，仅记录：

- `joint4` 的 `velocity` 限位是 1 rad/s，其余关节为 10（导出文件本身如此）；
- `joint6` 阻尼在 URDF 写 1.0、在 MJCF 写 2.0。运动学求解器不读 URDF 的 `dynamics`，
  仿真实际生效的是 MJCF 的 2.0。

## 验证

- URDF 与 MJCF 的 6 个关节限位、7 个连杆质量逐项一致；MuJoCo 正向运动学与 URDF FK
  在 30 组随机关节角上最大位置偏差 5.8e-16 m、姿态偏差 3.4e-6 deg（顺带确认 MJCF 的
  `eulerseq="zyx"` 与 URDF 的 rpy 约定一致）；
- `colcon build --packages-select arm_model` 通过；
- headless 起 `arm_controller_test_sim.launch.py`：硬件插件加载、6 个 actuator 全部注册，
  `joint_state_broadcaster` / `sim_pid_controller` / `arm_controller` 全部 active，
  `/joint_states` 收到 6 个关节且初始位置在零位附近。
