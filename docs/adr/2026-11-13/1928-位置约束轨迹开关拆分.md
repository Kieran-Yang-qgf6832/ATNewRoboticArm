# ADR-20261113-1928：位置约束轨迹开关拆分

- 状态：已采纳
- 日期：2026-11-13 19:28
- 相关：[real-compat 仿真方案](1928-real-compat仿真方案.md)、`src/arm_controller/controller/src/controller.cpp`

## 背景

`real_mode` 原本同时承担三件事：拒绝 `teach_pendant` / `measure`、拒绝位置约束轨迹
（`pos_move` / `box_move` / `cart_waypoints`）、以及标记实机 5 自由度。
这导致一个矛盾：real-compat 仿真想验证 5 维位置/工具轴任务，却因为 `real_mode=true`
把要验证的轨迹也一起拒掉；实机即使验证通过，也没有显式路径启用这些任务。

## 决策

把“实机物理上做不到的状态”和“位置约束轨迹的放行”拆成两个开关：

| 参数 | 语义 | 仿真默认 | 实机默认 |
| --- | --- | --- | --- |
| `real_mode` | 拒绝 `teach_pendant` / `measure` | `false` | `true` |
| `allow_constrained_traj` | 放行 `pos_move` / `box_move` / `cart_waypoints` | `true` | `false` |

- 两个参数都在 `ArmController::on_init` 中 `auto_declare`，构造期读取一次；
- 运行时禁止修改（参数回调里与 `joints` / `task_dim` 一起拒绝）；
- 启动日志同时打印两个实际值（`cart constraint:` 与 `task_dim=...` 两行）。

## 备选方案

- **保持 `real_mode` 一刀切**：最安全，但实机永远不能用视觉/位置任务。
- **real-compat 验证通过后直接删除拒绝逻辑**：少一个参数，但实机下次启动会自动启用
  未上机验证的路径，不可审计。
- **在任务层做拒绝**：任务层不是唯一入口（话题可直接发），拒绝必须放在控制器。

## 后果

- real-compat 仿真可以同时设置 `real_mode=true`（验证实机状态门禁）与
  `allow_constrained_traj=true`（放行被测轨迹）；
- 实机默认仍拒绝位置约束轨迹，验证通过后手动改 `ros2_controller_real.yaml` 并重启；
- 新增参数必须三处同步：`auto_declare`、controller YAML、读取处（C6 的教训）。
