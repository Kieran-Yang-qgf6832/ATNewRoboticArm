# O16 多路点规划逐段缩放时长，曲线过冲撞关节限位【高】（已修）

> 严重度：高 ｜ 状态：已修 ｜ 提交：`052494b` ｜ 日期：2026-11-12 14:55

> 2026-11-12。`waypoints_joint_8` 在仿真里**间歇性**失败：同一份 tasks.yaml、同一个序列，
> 有时 3.46 s 正常走完，有时在下发前被拒绝。失败日志：
> `位置过冲：t=6.517849 s 关节 0 位置 1.800177883 超出限位 [-1.8, 1.8]`。
> 路点本身最大只有 0.2 rad，离 1.8 很远，说明是规划器自己把曲线推出去的。

**根因**

旧实现按段**独立**缩放时长：

1. 用当前段时长 `T_i` 计算节点时刻，再用非均匀差商估计节点的 v/a/j；
2. 每段采样峰值，按 `T_i × ratio_i` 单独更新该段时长（还有一轮 `kMaxTightenRounds` 收尾）。

这两个步骤互相耦合：某段时长收缩到接近最小值后，它两端节点的差分分母 `Δt` 变小，
二阶/三阶导数被按 `1/Δt²`、`1/Δt³` 放大；七次 Bezier 的控制点里 `b3/b4` 又含
`T³·j` 与 `T²·a` 项，于是相邻段的控制点被推到关节限位之外。起点在 `reset_tolerance`
（0.01 rad）内的微小差异就足以改变迭代路径，所以表现为**偶发**失败。

**解决**

`src/arm_controller/lib/calculate/waypoint_trajectory.cpp` 改为：

- 以**归一化累计弧长** `u ∈ [0,1]` 为参数，节点导数只对 `u` 估计一次；
- 各段时间按 `Δu` 成比例，整体乘一个**全局** `T_total`；速度/加速度/jerk 峰值按
  `1/T`、`1/T²`、`1/T³` **解析**缩放，测一次即可定 `T_total`；
- 这样 Bezier 控制点只由路点几何决定、与 `T_total` 无关，位置过冲不再随“时间怎么分”
  变化；`total_duration` 只是对整条轨迹等比放大；
- 连续重合路点（例如自动补的起点恰好等于用户首点）直接合并；所有点重合时退化为
  一条静止轨迹，而不是零弦长除零。

**实测**

`waypoints_joint_8` 连续 3 次仿真全部通过，终点残差 **0.0000 rad**；自动时长
**10.09 s**（旧实现成功时约 3.46 s）。变慢是因为全局时间尺度由最紧的那个节点
jerk 决定，不能再让相邻段“各快各的”；换来的是**确定性**和几何上不可能过冲。

**教训**

- **时间分配不要和“用时间间隔做差分估计导数”耦合**：分段独立缩放会让估计量反馈到
  自己的分母上。几何参数化（弦长/弧长）+ 单一全局时间尺度更稳，且峰值缩放是解析的。
- **离线回归要覆盖真实路点和 reset 残差**：原来的 1..8 路点用例全是等间距共线点，
  数值条件最好，掩盖了不等间距 + 非零起点下的不稳定。`waypoint_planner_test` 现已加入
  `waypoints_joint_8` 的真实路点、4 个 reset 容差内起点、重合首点和全重合路点用例。
