# O22 导纳与拖动示教在 4 轴模型上不可用（外加力估计符号反了）【高】

> 严重度：高 ｜ 状态：已修 ｜ 日期：2026-10-21 2024

## 现象

1. `exp_state=admittance` 在 4 轴模型下被 `enter()` 显式拒绝（O21 的临时限制）。
2. `exp_state=teach_pendant` 一进去就报错退回 idel：日志是「任务速度长度不对：要 4 个，给了 6 个」
   ——`TeachPendantState` 把姿态缓存、零向量、FK 结果全部写死成 6 维。
3. 即使把维度改对，导纳的**力估计符号是反的**：注入 +5 N 的世界力，估计值是 **−4.76 N**。
   符号反了导纳会朝**背离**受力方向让开。这条只有「注入已知外力、比对估计值」才测得出来——
   只看「机械臂动了」会以为它在让开（其实是外力把它推走的）。

## 根因

| # | 问题 | 实测/结论 |
| --- | --- | --- |
| 1 | 4 维任务空间下的拒绝 | `enter()` 里 `if (task_dof_ != 6) return false`；M/D/K 与力估计其实都按 `task_dof_` 取值，拒绝是多余的 |
| 2 | 示教写死 6 维 | `task_zero_.setZero(6)` / `end_effector_pose_.resize(6)` / 尺寸校验 `!= 6` |
| 3 | **力估计符号** | 刚体动力学 `M·qdd + C + g = τ_act + τ_ext`，所以 `τ_act − RNEA = −τ_ext`。原代码把残差直接当外力 |
| 4 | 只有轨迹才有导纳 | `run()` 在 `!trajectory_active_` 时只做保持——「切进导纳被推着走」根本不会发生 |
| 5 | K = 0 时是无穷大直流增益 | 任何模型偏差都会被积成爬行；必须加死区（不是可选优化） |
| 6 | 近奇异位形放大 | 零位形完全伸直、z 向不可控，`J^T f = τ` 的最小二乘解被 1/σ_min 放大：实测 5 N 被估成 **78 N / 12 N·m**，直接写进力矩前馈把 joint4 推过限位（−3.85 rad，超出 ±1.5708） |
| 7 | body 系施力会跟着连杆转 | 外力服务按 body 局部系施加；机械臂一让开工具轴就转，整段力的**世界**方向跟着转（5 N 的推力在估计里出现 ~30° 偏角） |

## 修法

1. **自由导纳分支**（`AdmittanceState::run_free_roam`）：没有 `arm_admittance` 轨迹时，
   进入即把期望位置锁到当前位姿，之后按 `M·ẍ + D·ẋ = F_est` 积分（K 不参与）。
   收到轨迹仍走原来的「轨迹 + 柔顺」，且只对**柔顺部分**限速、不截断轨迹前馈速度。
2. **力估计**：`τ_ext = RNEA(q, dq, ddq_实测) − τ_act`（真实加速度来自 O8 的 acceleration
   状态接口；实机没有该接口时退回 ddq = 0），再经 `TaskMapping` 雅可比转成任务空间力。
   之后依次：**死区** → **一阶低通**（10 Hz，0 = 关闭）→ **限幅**（20 N / 3 N·m）。
3. **限速**：平移按**速度向量模长** 0.1 m/s，自转 0.5 rad/s（两个参数，可热更新）。
4. **边界**：逆解失败时回滚到上一拍可行目标 + 速度清零，**状态保持**，日志限流 ——
   推到工作空间边上不会掉回 idel。
5. **示教**：只改维度（`task_dof_` / `joint_count_`），零力语义不变（kp = 0、只留 kd 阻尼 + 重力前馈）。
6. **参数热更新**：`admittance_mass/damping/stiffness` 与新增的限速/死区/滤波/限幅都改成
   **真热更新**——参数回调写 `std::atomic<double>` 快照，`run()` 每拍读，不分配、不加锁。
   原先这三个数组「能 set 但不生效」（C6 那类静默陷阱），调手感会被误导。
7. **力估计出口**：控制器新增话题 `~/admittance_estimate`（`Float64MultiArray`，500 ms）：
   前 `task_dof` 个是**死区/滤波之前**的原始估计，后 `task_dof` 个是处理之后的值。
   这是「第 1 步力估计复核」的读出口。
8. **外力注入**：`launch_pack/config/mujoco_plugins.yaml` 加载 mujoco 的
   `ExternalWrenchPlugin`（服务 `/external_wrench_plugin/apply_wrench`），两个仿真 launch 都传。

**验收（`src/launch_pack/tools/admittance_demo_check.py`，一条命令、真实退出码）**

```
source install/setup.bash
python3 src/launch_pack/tools/admittance_demo_check.py --mode force       # 第 1 步：力估计复核
python3 src/launch_pack/tools/admittance_demo_check.py --mode admittance  # 推着走 / 撤力停
python3 src/launch_pack/tools/admittance_demo_check.py --mode teach       # 拖动示教
```

脚本自己起 headless 仿真、跑 `tasks.yaml` 的 `admittance_demo` / `teach_demo`、按 TF 把世界系力
换算成 link4 body 系后**分段**注入（防止工具转动改变世界方向），再用 TF/joint_states 断言。

## 代价与边界

1. **y 方向结构性不可用**：工作空间只有 4 cm，且臂在 y 上极硬——推 y 时位置环的顺应性
   几乎全落在 x/z 上，而且**让开方向不保证**：同一套代码两次实测 +y 分别是 **+1.1 cm** 与
   **−6.9 mm**（y 方向的雅可比最小，力估计在这里最弱）。y 只断言「对力有响应
   （|位移| ≥ 6 mm）」并记录符号，不做方向断言。
2. **不要在零位形直接进导纳**：零位形在边界、z 向奇异，力估计被放大（限幅前 78 N）。
   演示序列先 `joint_move` 到 `ready` 再进导纳。限幅把冲击压到 20 N / 3 N·m，但估计本身
   在该位形仍然不可信。
3. **body 系外力会跟着连杆转**：持续整段施力时工具轴一偏，世界方向就变。验收脚本按 0.2 s
   一段重算，手写测试要注意；否则会看到「估计值方向偏了几十度」而误判符号错。
4. **顺应性位移是物理的**：位置环刚度有限，撤力瞬间手臂会弹回、瞬时速度必然超限速，
   验收判据用「推力段的平均速度」而不是瞬时峰值。
5. **示教没有刹车**：零力模式只有 kd 阻尼，力给大了整条臂会飞出去（4 N / 0.9 s 实测走 0.65 m）。
   松手后约 1 s 停住，0.5 s 内可能还在慢慢滑。
6. **示教能拖出关节限位，且仿真里回不来**：零力模式（kp = 0）不施加软件限位，靠的是物理限位；
   实测把 joint4 拖到 **+4.39 rad**（限位 ±1.5708）后，MJCF 的软限位没能把它挡回去，
   之后 `reset` 也拉不回来（控制器打 "joint4 is outside its model limit" 并原地保持）。
   做拖动演示后建议重启仿真；实机上这一条要靠机械限位兜底。

6. **六轴路径未验证**：自由导纳、实测加速度、热更新、示教修复都是与任务维无关的共享代码，
   6 轴模型会一起变好但没有实测背书。

**教训**

1. **力的符号只能靠注入已知力验证**：残差法估计外力时，符号错和「手臂被外力推走」在现象上
   几乎一样。这次是靠「5 N → −4.76 N」这条数字发现的问题。
2. **「能 set 参数」和「参数生效」是两件事**：C6 的教训在导纳上又出现了一次——校验通过、
   返回值成功、但状态机从没读过新值。调手感前先确认生效路径。
3. **K = 0 的导纳必须带死区**：无穷大直流增益意味着任何偏差都会积分成位置漂移；
   死区大小要按实测的残差噪声/偏差标定（本模型静止时原始估计 3e-8 N，取 0.5 N 足够）。
4. **近奇异位形的估计要限幅**：`J^T f = τ` 在 σ_min 很小时给出非物理的大力；
   要么阻尼最小二乘，要么限幅 + 避开奇异位形（本次选了后者）。
