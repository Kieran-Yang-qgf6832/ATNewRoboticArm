# O22 rosbag 出图的状态带全为空——状态时间按绝对时间映射，却和相对时间轴比较

> 严重度：低 ｜ 状态：已修 ｜ 日期：2026-11-22 10:29

> 触发场景：`ros2 run launch_pack plot_rosbag <bag>` 画任何首帧反馈 `header.stamp` 不为 0 的 bag
> （所有实机 bag、仿真时钟不从 0 起的 bag）。图上一条状态背景带都没有，终端也不报错。
> 数据来源：`.ros/ros2bags/arm_sim_20261122-101142`（reset → idel）、
> `.ros/ros2bags/arm_real_20261122-093906`（idel → joint_traj）、
> `.ros/ros2bags/arm_real_20261116-215315`（5 段）。

## 现象

- bag 里 `/arm_controller/state` 明明录到了 2～6 条（reset / idel / joint_traj），
  出的 PNG 与 HTML 里都没有状态带，也没有状态名。
- 2026-11-14 那次验证没暴露：当时的仿真 bag 首帧反馈 `header.stamp` ≈ 0，
  绝对时间和相对时间刚好重合。

## 根因

`_state_segments` 把状态消息的 bag 接收时间经 `/joint_states` 的「接收时间 → header 时间」
线性映射，得到的是 header 的**绝对**时间（实机是系统时间，约 1.79e9 s；仿真也可能不是从 0 起），
之后直接和 `_build_curves` 的**相对**时间轴（首帧反馈 = 0）比较：

```python
mapped = np.interp(raw_time, bag_t, hdr_t) / 1e9        # 绝对秒
segments.append((max(start, t0), min(end, t1), ...))     # t0=0、t1=跨度（秒）
```

于是每段的 `start` 都是 1.79e9 量级、`end` 被 `min(..., t1)` 压到跨度，`end > start`
恒不成立，最后被 `[segment for segment in segments if segment[1] > segment[0]]` 全部过滤，
函数返回 `[]`——静默丢失，不是崩溃。

## 修复

映射完成后减掉首帧反馈的 header 时间，与曲线坐标统一到「首帧反馈 = 0」：

```python
mapped = mapped / 1e9 - float(feedback["time"][0]) / 1e9
```

## 验证

修复后同一函数对三个 bag 的输出：

- `arm_sim_20261122-101142`：reset 4.9–7.8 s、idel 7.8–73.9 s（2 段）；
- `arm_real_20261122-093906`：idel 3.8–16.3 s、joint_traj 16.3–200.7 s（2 段）；
- `arm_real_20261116-215315`：idel / joint_traj 交替 5 段，边界与 bag 里的状态序列一致；
- 无头 Chrome 渲染 `arm_sim_20261122-101142/joint1.html`，两段底色与 `reset` / `idel`
  标注都能看到；PNG 同步出现状态带。
