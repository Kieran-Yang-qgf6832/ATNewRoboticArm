# O18 模型更新后目标点未重测，多条笛卡尔演示序列失效

> 严重度：中 ｜ 状态：未修 ｜ 日期：2026-11-14 17:30

> 2026-11-14，跑 5 维容差改动的回归时发现：`pos_axis_demo` / `box_move_demo` /
> `real_compat_box` 全部在下发前被预检拒绝。不是容差问题，是 `tasks.yaml` 里
> **依赖模型的坐标从来没按新模型重测**。

**现象**

| 序列 | 结果 |
| --- | --- |
| `pos_move_demo` | 退出码 0，但位置残差 3.7 mm（位置判据对 `pos_move` 只告警，掩盖了问题） |
| `pos_axis_demo` | 预检拒绝：最近可达位姿仍差 0.207 m / 108.6° |
| `box_move_demo` | 5D 预检拒绝（48.2 mm / 7.8°）；回退 position-only 后仍拒（12.9 mm） |
| `real_compat_box` | 5D 预检拒绝（64.0 mm / 8.2°）；回退 position-only 后仍拒（6.7 mm） |

**根因**

`fb76cb4`「更新下模型」替换了 `base_link`–`link6` 的 STL、`robotic_arm.urdf`、
`robotic_arm.xml` 与 real-compat 场景（工作空间几何整体变了），但**没有**重新测量
`src/tasks/config/tasks.yaml` 里依赖几何的目标：

- `positions.ready_pos` 注释写明「由 fk_dump 在 ready 位形实测；换模型后必须重测」，
  但数值仍是旧模型：`[-0.147874, -0.015725, 1.232796]`。
  新模型 `fk_dump <urdf> 0 0.3 -0.3 0 0.3 0` 得到 `[-0.521426, 0.005496, 1.135222]`，
  两者差 0.38 m。
- `box_pregrasp` / `box_pregrasp_5dof` / `box_pregrasp_5dof_high` / `box_low_pregrasp`
  是旧模型下「视觉目标 5D IK 解与 ready 插值」的产物；新模型下同一个关节角
  `box_pregrasp` 落在 `x ≈ -0.685`，而视觉目标面在 `x ≈ +0.566`，方向都不对。
- `pos_axis_demo` 的两个 `orientation` 四元数按旧 ready 姿态构造，新模型 ready 的
  工具 z 已不同（`[0.49, 0.31, -0.81]`），目标姿态同样失效。

**影响**

- 上表四条序列目前都不能作为回归/验收用例；
- `pos_move_demo` 因为位置残差只告警，看起来「通过」，实际目标已偏 0.38 m；
- 实机 / real-compat 的验收链（`real_compat_box`）暂时不可用。

**待办（未做）**

1. 用新模型重测 `positions` 三个点（`fk_dump`，ready 位形）；
2. 重算三个 `box_pregrasp*` / `box_low_pregrasp`（视觉目标 5D IK + 与 ready 插值）；
3. 重算 `pos_axis_demo` 的两个 `orientation`（新 ready 姿态的最小旋转目标）；
4. 重跑四条序列并更新各文档里的「实测残差」数字。
