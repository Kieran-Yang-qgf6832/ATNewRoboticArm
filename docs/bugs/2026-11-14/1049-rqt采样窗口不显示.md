# O17 rqt 采样窗口不显示，实为等 TF 阻塞插件初始化【中】（已处理）

> 严重度：中 ｜ 状态：已处理 ｜ 提交：`—` ｜ 日期：2026-11-14 10:49

**现象**

`ros2 launch view calib.launch.py` 之后只看到 OpenCV 的 `calib board detector` 预览窗口，
**没有 rqt 采样窗口**；终端没有报错，`rqt_calibrator.py` 进程还活着。同一时刻
`handeye_server` 每 10 s 打一条：

```
The specified tf frames for the robot base and hand do not seem to be connected
Underlying tf exception: "link6" passed to lookupTransform argument source_frame does not exist.
Waiting for TF initialization...
```

**根因**

两个上游设计细节叠加，把窗口卡在了“创建”之前：

1. `handeye_server` 只在 `wait_for_tf_init()` 成功后才 `create_service(...)`：

```48:52:src/easy_handeye2/easy_handeye2/easy_handeye2/handeye_server.py
    def setup_services_and_topics(self):
        if not self.sampler.wait_for_tf_init():
            self.get_logger().warning('Waiting for TF initialization...')
            return
```

`setup_timer` 每 2 s 调一次，而 `wait_for_tf_init` 单次最多等 10 s，所以日志是 10 s 一条。

2. `rqt_calibrator` 的 `HandeyeClient.__init__` 用**无超时**的 `wait_for_service()` 等这些服务，
   而它跑在插件的 `init_plugin()` 里，于是 rqt 主窗口还没 `show()` 就阻塞住了：

```18:26:src/easy_handeye2/easy_handeye2/easy_handeye2/handeye_client.py
        self.node.get_logger().info('Waiting for sampling services')
        self.get_sample_client = self.node.create_client(ehm.srv.TakeSample, hec.GET_SAMPLE_LIST_TOPIC)
        self.get_sample_client.wait_for_service()
```

缺 `base_link -> link6` 的直接原因是只起了视觉，没起 `arm_real.launch.py`（详见
[09 手眼标定](../../execute/09-手眼标定.md)）。换句话说：**采样窗口的存在前提是机器人 TF 已就绪**，
而启动顺序反过来时不会有任何提示窗口。

**修法**

不改第三方代码：

- `09-手眼标定.md` 把启动改成“两个终端，先机械臂后视觉”，并写明所需 TF；
- 把“rqt 不出现 = 缺 `base_link -> link6`”写进同一篇的「已知坑」，附日志特征；
- 采样阶段不启动 `handeye.launch.py`（它的静态外参与 easy_handeye2 的 dummy 发布器抢同一个
  子帧 `camera_link`），复测阶段用 `start_handeye:=false` 关掉 dummy。

**验证**

补起 `arm_real.launch.py` 后无需重启 `calib.launch.py`：服务一旦创建，阻塞中的
`wait_for_service()` 立即返回，rqt 窗口在 2~4 s 内自动弹出。判定依据是
`Waiting for sampling services` 之后出现 `Configuring HandeyeClient ...` 的后续动作，
且 `ros2 service list | grep handeye` 能看到 `/arm5dof_realsense/take_sample` 等服务。
