# O20 出图工具在命令时间戳重复时崩溃：去重只裁数组不裁时间轴

> 严重度：低 ｜ 状态：已修 ｜ 日期：2026-11-15 14:25

> 触发场景：`ros2 run launch_pack plot_rosbag <bag>`，bag 里 `/arm_controller/joint_command`
> 存在两条 **header.stamp 完全相同**的记录（这次是 3902 条里重复 1 条）。

## 现象

```
File ".../plot_rosbag", line 272, in _interp_to
    out[inside, column] = np.interp(t_dst[inside], t_src, values[:, column])
ValueError: fp and xp are not of the same length.
```

工具在读 bag 之后、画第一张图之前就退出，一张图都不产出。

## 根因

`_sorted_unique()` 的用途是「按时间排序 + 去掉重复时刻」，实现却只把 `keep` 掩码用在了
数组上：

```python
# src/launch_pack/tools/plot_rosbag.py
keep = np.concatenate(([True], np.diff(t) > 0))
return (t,) + tuple(array[keep] for array in arrays)
```

返回的时间轴 `t` 仍是去重前的长度（3902），而 `pos/vel/eff` 已经变成 3901 条。
后续 `_interp_to()` 把它当 `xp/fp` 传给 `np.interp`，两者长度不一致直接抛异常。

为什么之前没暴露：只有「同一毫秒内两条命令的时间戳完全相同」时才会触发。`~/joint_command`
由 100 Hz wall timer 发布，快照里的 `stamp_ns` 取自控制周期，正常不会重复；这次是录制
时间与快照重复叠加出的偶发重复。

## 修复

时间轴与数组一起过 `keep`：

```python
return (t[keep],) + tuple(array[keep] for array in arrays)
```

## 验证

同一个 bag（`.ros/ros2bags/arm_sim_20261115-142515`，3902 条命令、1 条重复）修复后正常
产出 6 张图；重复时刻只保留最后一条，`np.interp` 的 x 严格递增。
`arm_sim_20261115-142332` / `-142427` 两个 bag 同样正常出图。
