# O19 每段轨迹首末跳动：保持力矩与轨迹力矩不在同一工作点【高】（仿真与实机均出现，未修）

> 严重度：高 ｜ 状态：未修 ｜ 日期：2026-11-15 09:13

> 触发场景：逐段下发 `/arm_joint_traj`（每段 `seconds=[0.0, 3.0]`，`wp0` = 发送时刻实测位姿、
> `wp1` = 目标），每段**开始与结束的瞬间**机械臂都会「跳」一下。
> **仿真与实机都出现**：仿真用 `arm_controller_test_sim.launch.py` / `arm_task_sim.launch.py`，
> 实机用 `arm_real.launch.py`。

## 现象

- 仿真、实机均在段首和段末各出现一次跳动；段内跟随正常。
- 仿真 bag `arm_sim_20261114-150116`（第 2 段：joint3 单独摆到 −2.0944）里能量化到
  两层证据（时间以该 bag 首条命令为 0）：
  - **命令侧（跳变的源头）**：段末 t=46.72 s，位置命令在一个 10 ms 采样内
    joint4 −0.8727 → −0.5295（**+0.343 rad**，等效 34 rad/s）、joint2 +0.215、
    joint6 −0.218、joint3 +0.142 rad；同一帧力矩命令 joint2 +12.09 → +14.03、
    joint4 −0.54 → +0.84 N·m。段首位置命令则有一个来自 `wp0` 的小台阶。
  - **响应侧（跳动本身）**：边界 ±50 ms 内反馈位置极差 joint4 0.0071 rad、joint2 0.0033 rad，
    反馈速度在一帧内变化 joint4 0.077 rad/s、joint2 0.025 rad/s。仿真的"跳"是加速度突变，
    没有固件位置环与机械柔度，所以痕迹比实机小，但机制相同、确实存在。
- 实机同一时刻的跳动肉眼明显，且伴随一下闷响/回弹（操作者描述）。

## 根因

三条机制叠加，前两条在仿真与实机都存在，第三条只在实机（或实机上被放大）：

**1. 段末把保持命令锁存到实测位置（仿真/实机共有）**

```1457:1462:src/arm_controller/arm/arm_fsm.cpp
        if (trajectory_finished(traj, traj_start_time_, time)) {
            traj.stop();
            state = TrajPhase::STOP;
            // 轨迹结束时锁存终点（理由同 CartTrajState::run）。
            latch_joint_position(factory, joint_count_, &hold_position_);
        }
```

`latch_joint_position` 取的是**实测**关节角，于是保持命令在一帧内跳到实际位置，
幅度恰好等于该段积累的跟踪误差（仿真 0.14–0.34 rad）。这一跳同时把位置误差清零：
原本用于把机械臂"拽"向目标的恢复力矩在一帧内消失 → 加速度突变。

**2. 段首 `wp0` 取发送时刻的实测位姿（仿真/实机共有）**

上位机把 `wp0` 填成发送时的实测值。实机状态是 50 Hz 上报 + 传输延迟（`/joint_states`
由 100 Hz 控制周期重发），仿真里也有 500 ms 的状态发布滞后；若这期间机械臂因下垂或回弹
移动过，第一帧命令就是一个位置台阶。

**3. 保持力矩与轨迹力矩不在同一工作点（实机放大项，仿真被配置掩盖）**

| 路径 | 力矩来源 | 实机实际值 |
| --- | --- | --- |
| 段间/段末保持 | `command.torque = gravity_.torque(i)`（`arm_fsm.cpp:146`） | **0**（`gravity_compensation: false` → `refresh()` 返回 false，`torque()` 恒 0） |
| 轨迹段 | `command.torque = torque(i)`，即 RNEA（`arm_fsm.cpp:1449-1453`） | 完整逆动力学，同姿态 joint2 约 **21 N·m** |

`ArmRealInterfaces::write()`（`arm_real_interfaces.cpp:351-356`）把 `effort` 原样写进 MCU
下行帧的 `torque` 槽，**不限幅、不斜坡**，固件直接叠加到速度环输出。段首一帧内 0 → ~20 N·m
（位置环静差塌陷，向上窜），段末 ~20 N·m → 0（重力压回位置环，下沉/回弹）。
仿真是 `gravity_compensation: true`，保持力矩 ≈ RNEA，所以这一项在仿真里不存在
（bag 里 43.72 s 处 joint2 21.111 → 21.088 连续），仿真的跳动只来自第 1、2 条。

## 修复方向（未实施，涉及实机安全需单独决策）

1. 让保持段输出**同一姿态的重力项**：实机打开 `gravity_compensation`，
   `gravity_compensation_scale` 从 0.1 逐步加。
2. 力矩前馈在段首末做 100–200 ms 斜坡，让固件侧看不到阶跃。
3. 段首 `wp0` 改用「当前命令位置」而不是实测位姿，消掉起点台阶。
4. 段末锁存策略可选：锁存**轨迹终点**（命令连续，但机械臂会被拉回未到达的终点）
   或锁存实测（不拉回，但命令不连续）——当前选择是后者，若改前者需要先确认跟踪误差量级。

## 验证

- 仿真：`ros2 run launch_pack plot_rosbag <bag>`，检查段边界处 `joint_command.position`
  的单样本跳变与 `effort` 台阶（bag 里面已有数据）。
- 实机：录一条实机 bag（launch 默认就录），按段边界检查
  `joint_command.effort` 是否一帧内 **0 ↔ 数十 N·m** 阶跃（第 3 条主因），
  以及 `joint_states.velocity` 在边界后 1–3 个采样是否有尖峰。

## 残留问题

- 实机 `/joint_states` 是 100 Hz 重发的 50 Hz MCU 数据，几十毫秒的冲击可能被削平；
  命令侧（`joint_command`）比响应侧可靠。
- 实机 joint6 无电机，`/joint_states` 里是指令镜像值，不能用来判断跳动。
