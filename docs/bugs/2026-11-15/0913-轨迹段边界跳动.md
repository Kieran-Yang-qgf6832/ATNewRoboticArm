# O19 每段轨迹首末跳动：保持力矩与轨迹力矩不在同一工作点【高】（仿真与实机均出现）

> 严重度：高 ｜ 状态：已修（仿真已验，实机待复测） ｜ 日期：2026-11-15 09:13

> 触发场景：逐段下发 `/arm_joint_traj`（每段 `seconds=[0.0, 3.0]`，`wp0` = 发送时刻实测位姿、
> `wp1` = 目标），每段**开始与结束的瞬间**机械臂都会「跳」一下。
> **仿真与实机都出现**：仿真用 `arm_controller_test_sim.launch.py` / `arm_task_sim.launch.py`，
> 实机用 `arm_real.launch.py`。

## 现象

- 仿真、实机均在段首和段末各出现一次跳动；段内跟随正常。
- 仿真 bag `arm_sim_20261114-150116`（第 2 段：joint3 单独摆到 −2.0944）里能量化到
  两层证据（时间以该 bag 首条命令为 0）：
  - **命令侧（跳变的源头）**：段末 t=46.72 s，位置命令在一个 10 ms 采样内
    joint4 −0.8727 → −0.5295（**+0.343 rad**，等效 34 rad/s）、joint2 +0.215、
    joint6 −0.218、joint3 +0.142 rad；同一帧力矩命令 joint2 +12.09 → +14.03、
    joint4 −0.54 → +0.84 N·m。段首位置命令则有一个来自 `wp0` 的小台阶。
  - **响应侧（跳动本身）**：边界 ±50 ms 内反馈位置极差 joint4 0.0071 rad、joint2 0.0033 rad，
    反馈速度在一帧内变化 joint4 0.077 rad/s、joint2 0.025 rad/s。仿真的"跳"是加速度突变，
    没有固件位置环与机械柔度，所以痕迹比实机小，但机制相同、确实存在。
- 实机同一时刻的跳动肉眼明显，且伴随一下闷响/回弹（操作者描述）。

## 根因

三条机制叠加，前两条在仿真与实机都存在，第三条只在实机（或实机上被放大）：

**1. 段末把保持命令锁存到实测位置（仿真/实机共有）**

```1457:1462:src/arm_controller/arm/arm_fsm.cpp
        if (trajectory_finished(traj, traj_start_time_, time)) {
            traj.stop();
            state = TrajPhase::STOP;
            // 轨迹结束时锁存终点（理由同 CartTrajState::run）。
            latch_joint_position(factory, joint_count_, &hold_position_);
        }
```

`latch_joint_position` 取的是**实测**关节角，于是保持命令在一帧内跳到实际位置，
幅度恰好等于该段积累的跟踪误差（仿真 0.14–0.34 rad）。这一跳同时把位置误差清零：
原本用于把机械臂"拽"向目标的恢复力矩在一帧内消失 → 加速度突变。

**2. 段首 `wp0` 取发送时刻的实测位姿（仿真/实机共有）**

上位机把 `wp0` 填成发送时的实测值。实机状态是 50 Hz 上报 + 传输延迟（`/joint_states`
由 100 Hz 控制周期重发），仿真里也有 500 ms 的状态发布滞后；若这期间机械臂因下垂或回弹
移动过，第一帧命令就是一个位置台阶。

**3. 保持力矩与轨迹力矩不在同一工作点（实机放大项，仿真被配置掩盖）**

| 路径 | 力矩来源 | 实机实际值 |
| --- | --- | --- |
| 段间/段末保持 | `command.torque = gravity_.torque(i)`（`arm_fsm.cpp:146`） | **0**（`gravity_compensation: false` → `refresh()` 返回 false，`torque()` 恒 0） |
| 轨迹段 | `command.torque = torque(i)`，即 RNEA（`arm_fsm.cpp:1449-1453`） | 完整逆动力学，同姿态 joint2 约 **21 N·m** |

`ArmRealInterfaces::write()`（`arm_real_interfaces.cpp:351-356`）把 `effort` 原样写进 MCU
下行帧的 `torque` 槽，**不限幅、不斜坡**，固件直接叠加到速度环输出。段首一帧内 0 → ~20 N·m
（位置环静差塌陷，向上窜），段末 ~20 N·m → 0（重力压回位置环，下沉/回弹）。
仿真是 `gravity_compensation: true`，保持力矩 ≈ RNEA，所以这一项在仿真里不存在
（bag 里 43.72 s 处 joint2 21.111 → 21.088 连续），仿真的跳动只来自第 1、2 条。

## 修复（2026-11-15 已实施）

三条机制对应三处改动，全部在控制器侧。取舍与备选方案见
[ADR-20261115-1131 参考连续性与力矩限速](../../adr/2026-11-15/1131-参考连续性与力矩限速.md)。

1. **段末锁存「最后一帧命令」**（`arm_fsm.cpp` 的 `latch_command_position()`）：
   `arm_joint_traj`、`arm_cart_traj` 与两条多路点路径在结束时不再取实测，而是把本周期
   刚写下的 `command_` 冻结成保持位置——命令全程连续，剩余跟踪误差交给伺服继续消。
   `idel` / `reset` / 故障保持**仍然锁实测**，那是「停」的语义；它们的力矩冲击由第 3 条兜住。
2. **段首用上一帧命令覆盖首点**（`rebase_first_point_on_last_command()`）：
   `arm_joint_traj` 装载后把首点位置改写成 `command_[i].position`，`arm_joint_waypoints`
   的首节点也取命令。发布者的 `wp0` 是发送时刻的实测，与命令差一个等待期的塌陷/下垂。
   笛卡尔路径**没改**：它的首点是位姿、每周期用实测做 IK 初值，要让它连续是另一处
   风险更高的改动（见 ADR 的「未覆盖」）。
3. **力矩前馈在控制器出口限速**（新参数 `torque_slew_rate`，N·m/s，0 = 关闭，默认 300）：
   `ArmController::update()` 写命令接口前过 `limit_effort_slew()`，故障保持路径同样过。
   实机 100 Hz 下 21 N·m 的阶跃 = 7 帧 ≈ 70 ms。`measure` / `teach_pendant` **豁免**：
   它们自己产生前馈（激励轨迹、示教重力项），削峰等于改写真正下发的力矩。
4. **两条只报告的 WARN**：段末 `|轨迹终点 − 实测| > 0.1 rad`、段首
   `|首发点 − 上一帧命令| > 0.1 rad` 各打一条。选了「锁存终点」之后，没跟上的偏差会变成
   持续的位置误差；不打日志它只是从「一跳」变成「一直偷偷偏在那里」。

原计划的四个方向：方向 1（实机打开重力补偿）**未采用**——需要上机核实 RNEA 力矩符号与
幅值，本次无法验证；方向 2 = 第 3 条；方向 3 = 第 2 条；方向 4 选了「锁存轨迹终点」这一支，
代价是段末会有一次可见的回弹。

## 验证

**仿真**（2026-11-15 11:24 起，bag `.ros/ros2bags/arm_sim_20261115-112444`，按 O19 的触发
方式逐段下发 `/arm_joint_traj`：先复现原 bag 的位形——joint2/joint4 = −0.873 下把 joint3
从 −0.873 摆到 −2.0944；再把一段四轴大幅换向压到 0.7 s 制造段末偏差）：

| 指标 | 判据 | 实测 |
| --- | --- | --- |
| 段边界单帧位置跳变 `\|Δpos\|` | ≤ 0.01 rad | **0.0000–0.0002 rad**（13 个段末 / 12 个段首；唯一 0.0063 是 reset→idel，不是轨迹边界） |
| 段边界单帧力矩跳变 `\|Δeffort\|` | ≤ 300 N·m/s | **3.000 N·m / 100 Hz 采样 = 300 N·m/s**（控制周期 2 ms 上即 0.6 N·m），正好压上限 |
| 段末跟踪偏差 | 记录 | 最大 **0.305 rad**（joint1，0.7 s 那段） |
| 段末偏差 1 s 内收敛 | ≤ 0.02 rad | **0.304 → 0.012 rad** |
| 段末偏差告警 | > 0.1 rad 打 WARN | 触发一次：`joint_traj: trajectory finished with 0.308 rad tracking deviation at joint1` |

修复前的基线（同一条 O19 bag）：段末命令单帧跳变 0.343 rad（joint4）；修复后同类边界
0.0000 rad。

**笛卡尔回归**（2026-11-15 13:56，`arm_task_sim.launch.py task_sequence:=ready_then_cart`，
bag `arm_sim_20261115-135652`）：`joint_move` → `cart_move` 串联正常，笛卡尔位置残差
0.0007 m；6 个段末 / 5 个段首的位置跨界跳变 0.0000–0.0050 rad、力矩跨界变化 ≤ 0.020 N·m。
笛卡尔段首按计划**没有改**（它的下垂台阶仍在，见 ADR 的「未覆盖」）。

**重复性（2026-11-15 14:23–14:26 再跑三次）**：`arm_sim_20261115-142332`（O19 原样，3 s 段）、
`-142427`（0.7 s 短时长，专门制造段末偏差）、`-142515`（常规多段 2.5 s）。轨迹段之间的
位置跨界跳变 0.0000–0.0020 rad；`reset → idel` 的状态切换 0.0050–0.0063 rad（这条仍锁实测，
但远小于原来的 0.343）；力矩跨界变化最大 3.000 N·m（= 300 N·m/s，压在限速上）；段末偏差
最大 0.305 rad，1 s 后 0.012 rad。三次结果与上表一致。

**实机**：待复测。除了上面两条指标，还要看 `joint_command.effort` 在段边界是否按
300 N·m/s 斜坡而不是一帧 0 ↔ 20 N·m，以及 `joint_states.velocity` 在边界后 1–3 个采样
是否还有尖峰。

**未覆盖**：`measure` / `teach_pendant` 的豁免只在代码层面审过，本次没跑辨识链路。

## 残留问题

- 实机 `/joint_states` 是 100 Hz 重发的 50 Hz MCU 数据，几十毫秒的冲击可能被削平；
  命令侧（`joint_command`）比响应侧可靠。
- 实机 joint6 无电机，`/joint_states` 里是指令镜像值，不能用来判断跳动。
