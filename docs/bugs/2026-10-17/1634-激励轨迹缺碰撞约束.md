# O12 激励轨迹没有自碰撞与连杆-地面碰撞约束【高】

> 严重度：高 ｜ 状态：已修 ｜ 提交：`42a5d55` ｜ 日期：2026-10-17 16:34

**现象**

O11 只解决了「末端工具别插进地面」，激励轨迹仍然可能把机械臂扭成**自碰撞**位形，
也没管**除末端外**其它连杆与地面的碰撞。实测：

- 在关节行程内均匀随机采样 1000 个位形，**11 个处于自碰撞**（link1↔link4/5/6、
  link2↔link4、base_link↔link3/4），最多同时 5 对；
- 用 python-pinocchio 对旧的辨识数据（2026-10-12 的 CSV）复算：在从不碰撞的几对里，
  **p5 分位最小距离约 0.028 m**（link3↔link5）、p1 分位 0.021 m；而 link1↔link4/5/6、
  link2↔link4/5/6 的 p1 分位已经到 0（存在自碰撞样本）；
- URDF 里没有地面，link4/link5/link6 的网格在部分位形下会低于 z=0。

这和 O11 是同一个物理机制：MuJoCo 的接触冲量在辨识模型里无法解释，全部变成残差；
实机上则是直接撞坏结构。

**修法**

1. `ExcitationTrajectory` 构造时用 `pinocchio::urdf::buildGeom` 加载 URDF 的
   `<collision>` STL 网格（与 MuJoCo 仿真**同一套几何**），构建 GeometryModel：
   - **连杆间碰撞对**：去掉相邻对（parentJoint 相差 ≤ 1）后 15 对。相邻对的网格在关节处
     本来互相嵌入（实测任意位形距离恒为 0），MuJoCo 的 scene.xml 也用 `<contact><exclude>`
     排除了它们——不排除的话可行域恒为空；
   - **地面对**：coal::Plane 位于 z = 0（与 scene.xml 的 ground plane 一致），每个连杆
     各一对，**排除 base_link**——它的网格从 z = -0.0095 开始（安装座埋进地面），而仿真里
     base_link 是静态体，MuJoCo 不算静态体之间的接触，纳入约束会让可行域恒为空。
2. **约束形式**：coal 的**带安全裕度碰撞查询**（`CollisionRequest::security_margin`）。
   碰撞即表示距离 < 安全间距，累计 +1；与其它约束同属一个累加量。
3. **新参数**（都在 `ArmController::on_init` 里 auto_declare，0 = 关闭）：
   - `measure_traj_collision_safe_distance`（默认 0.02 m）
   - `measure_traj_ground_clearance`（默认 0.01 m）
4. **旧约束让位**：`measure_end_effector_z_lower_limit` 默认从 0.20 改回 `-.inf`。
   新地面约束卡的是每个连杆的网格最低点，比旧的单点约束严格且更合理；旧参数保留作
   O11 的回归基准与逃生开关。

**性能选型（关键，别走回头路）**

在 22 对稠密 STL 网格（link1 有 68k 三角形）上实测：

| 方案 | 单采样点耗时 | 结论 |
| --- | --- | --- |
| `computeDistances` 完整距离查询 | **79 ms** | ✗ 1000 点 × 1500 次评估 = **33 小时** |
| 带安全裕度碰撞查询 | 1.24 ms | 可行但偏贵 |
| **世界 AABB 预筛 + 上述精确查询** | **0.94 ms** | ✓ **采用** |
| 纯世界 AABB 距离 | 7 µs | ✗ 太保守：20 mm 时 1000/1000 样本误报 |
| 连杆局部包围盒（coal::Box） | 7 µs | ✗ 太保守：20 mm 时 82% 样本误报 |
| 无裕度布尔碰撞 | 40 µs | 可用但没有安全间距 |
| 凸包（coal::Convex） | — | ✗ ROS 的 coal 未编译 qhull，构造直接抛异常 |

AABB 预筛是**保守**的：世界 AABB 距离是网格距离的下界，AABB 距离 ≥ 安全间距时
真实距离必然也 ≥ 安全间距，跳过精确查询不会漏判（实测漏报数 0）。
另外，采样点若已经违反软限位/力矩/速度，就跳过碰撞检查——早期种群大量候选都如此，
这一条省掉了大部分计算。

**实测**

seed=1 端到端跑 measure（`csv_file_path:=/tmp/o12_measure_final.csv`）：

- 生成日志：`激励约束：… 连杆间安全间距 0.0200 m，地面净空 0.0100 m，碰撞违例 0.000e+00`
- 激励得分 **2.2140**（O11 修复后的 seed=1 是 2.121，O11 之前 2.165）——旧的 0.20 m 末端
  z 下限关掉后激励空间变大，碰撞约束没有把得分压下去；
- 轨迹生成耗时约 **54 s**，任务层默认 30 s 的 `step_timeout` 会误判失败 →
  `arm_measure_sim.launch.py` 的 `step_timeout` 默认值提到 **240 s**；
- 记录轨迹（实际关节角，含跟踪误差）用 `check_collision.py` 复算精确距离：
  **见下方验证小节**。

**验证（记录轨迹的实际关节角，不是指令值）**

```
python3 src/parameter_identify/tools/check_collision.py \
    src/arm_model/model/robotic_arm.urdf /tmp/o12_measure_final.csv 0.02 0.01
```

实测记录轨迹 **4995 个样本**（实际关节角，含跟踪误差）：

| 检查项 | 结果 |
| --- | --- |
| 连杆间最小距离（15 对非相邻对，要求 >= 0.02 m） | **0.0332 m**（link3↔link5） |
| 第二近的一对 | link4↔link6 **0.0365 m** |
| 连杆离地净空（6 对，base_link 除外；要求网格最低点 >= 0.01 m） | **link1 最低 z = 0.012 m**（距 z=0.01 平面 +0.0020 m）；其余 >= 0.075 m |
| 违例样本数 | **连杆间 0，钻地 0** |

对照：同一判据（20 mm 安全间距）下，2026-10-12 的旧数据 link3↔link5 最小距离是
**0.0284 m**——刚好擦着 20 mm 过；而随机位形里 11/1000 会自碰撞，说明旧轨迹能通过
只是**运气**，不是约束保证的。O12 之后无论 seed 取多少，输出轨迹都经过同一个检查。

**教训**

1. **性能数据要按真实规模算，不能拍脑袋**：一开始按「0.15 ms/次」估的预算，实际距离查询
   是 79 ms——放大 500 倍，方案直接不可用。选型前先在真实几何上跑基准。
2. **保守的代理几何（AABB/包围盒）不能直接当约束**：它们保证"不漏判"，但会大量误报
   （20 mm 时 82%~100% 样本），把激励空间压没。它们只适合做**预筛**。
3. **"包含所有连杆"这种直觉要先验证几何事实**：base_link 的网格本来就在地面以下 9.5 mm，
   纳入地面约束会让可行域恒为空。仿真里它是静态体，MuJoCo 根本不算它对地面的接触。
4. **新约束会改变总耗时，必须同步检查任务层超时**：加碰撞约束后生成实测约 54 s，
   而任务层当时默认 30 s 的 `step_timeout` 会把一次成功的测量误判成失败
   （现已提高到 240 s）。
